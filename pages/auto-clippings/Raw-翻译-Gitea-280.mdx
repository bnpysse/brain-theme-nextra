【文章标题】：Gitea 28.0

【文章正文】：

We are thrilled to announce the latest release of Gitea v28.0.0.

我们非常兴奋地宣布Gitea v28.0.0的最新版本发布。

Gitea drops the historical 1. prefix from its version numbers, so this release is 28.0.0 rather than 1.28.0.

Gitea移除了版本号中历史遗留的1.前缀，因此本次版本号为28.0.0而非1.28.0。

Highlights include audit logging, bot accounts, HTTPS deploy tokens, user impersonation for administrators, code-owner approval rules, diff file filters, and an Actions queue view. See the changelog for everything else.

主要亮点包括审计日志、机器人账户、HTTPS部署令牌、管理员用户模拟、代码所有者审批规则、差异文件过滤器以及Actions队列视图。其他更新请参阅变更日志。

We are very thankful for the many people who have contributed to the project by sending code patches, reporting issues, translating, and supporting us in many other ways.

我们衷心感谢所有通过提交代码补丁、报告问题、翻译以及以其他多种方式支持该项目的人们。

How to Update

如何升级

Section titled "How to Update"

本节标题："如何升级"

You can download Gitea from our downloads page. Please read our installation guide for more information. Before upgrading, read the breaking changes. Then back up your data, replace the binary or Docker container, and restart.

您可以从下载页面获取Gitea。更多信息请阅读安装指南。升级前请务必阅读重大变更说明，然后备份数据、替换二进制文件或Docker容器并重启服务。

Release binaries no longer include 32-bit x86 or gogit builds, and the Snap is no longer built for armhf. Download file names also no longer carry an OS version suffix, for example gitea-28.0.0-windows-amd64.exe, so update any download scripts.

发布版二进制文件不再包含32位x86或gogit构建版本，Snap包也不再支持armhf架构。下载文件名也不再携带操作系统版本后缀（例如gitea-28.0.0-windows-amd64.exe），请相应更新下载脚本。

Major Breaking Changes

重大变更说明

Section titled "Major Breaking Changes"

本节标题："重大变更说明"

⚠️ Git network operations use an internal proxy and new egress rules (#39426)

⚠️ Git网络操作使用内部代理及新出口规则(#39426)

Section titled "⚠️ Git network operations use an internal proxy and new egress rules (#39426)"

本节标题："⚠️ Git网络操作使用内部代理及新出口规则(#39426)"

Migrations, mirrors, and other Git network operations now go through an internal proxy that applies the egress settings to direct connections. Review your allow and block lists before upgrading:

迁移、镜像和其他Git网络操作现在会通过应用出口设置的内部代理进行直连。升级前请检查您的允许和阻止列表：

- The external preset is removed. For a deny-by-default policy, setEGRESS_MODE = strict and list the allowed hosts.[migrations] EGRESS_MODE covers migrations and mirrors, and[security] EGRESS_MODE covers webhooks and OAuth2.

- 移除了外部预设。如需默认拒绝策略，请设置EGRESS_MODE = strict并列出允许的主机。[migrations] EGRESS_MODE适用于迁移和镜像，[security] EGRESS_MODE适用于webhook和OAuth2。

- In strict mode, entries without a port only allow ports 80 and 443.

- 在严格模式下，未指定端口的条目仅允许80和443端口。

- In the default lax mode,[security] ALLOWED_HOST_LIST no longer restricts public hosts. Set[security] EGRESS_MODE = strict to keep it as an exclusive allowlist. Gitea logs a startup warning when the list is set without an explicitEGRESS_MODE .

- 在默认宽松模式下，[security] ALLOWED_HOST_LIST不再限制公共主机。设置[security] EGRESS_MODE = strict可将其作为专属白名单。当设置了该列表但未明确指定EGRESS_MODE时，Gitea会记录启动警告。

- IP address entries no longer accept wildcards, and * is no longer a valid entry.

- IP地址条目不再接受通配符，*不再是有效条目。

- Domain entries follow curl syntax: example.com matches the domain and all subdomains,*.example.com matches only subdomains, andexample.* is invalid.

- 域名条目遵循curl语法：example.com匹配该域名及其所有子域名，*.example.com仅匹配子域名，example.*无效。

- Invalid [migrations] BLOCKED_HOST_LIST entries now stop Gitea from starting.

- 无效的[migrations] BLOCKED_HOST_LIST条目现在会阻止Gitea启动。

- [migrations] ALLOWED_DOMAINS ,BLOCKED_DOMAINS , andALLOW_LOCALNETWORKS are deprecated in favor of[migrations] ALLOWED_HOST_LIST andBLOCKED_HOST_LIST .

- [migrations] ALLOWED_DOMAINS、BLOCKED_DOMAINS和ALLOW_LOCALNETWORKS已被弃用，建议改用[migrations] ALLOWED_HOST_LIST和BLOCKED_HOST_LIST。

Thank you to @TheFox0x7 for contributing this change.

感谢@TheFox0x7贡献此变更。

⚠️ Actions运行历史现在会过期(#38855)

Section titled "⚠️ Actions run history now expires (#38855)"

本节标题："⚠️ Actions运行历史现在会过期(#38855)"

Completed Actions runs are now deleted after 400 days by default, together with their jobs, logs, and artifacts. The new cleanup_action_runs cron task deletes them, by default at midnight. To keep all runs, set the following before upgrading:

已完成的Actions运行现在默认400天后会被删除，包括其任务、日志和制品。新的cleanup_action_runs定时任务会在午夜执行删除操作。如需保留所有运行记录，请在升级前设置以下参数：

0 now means "keep forever" for RUN_RETENTION_DAYS, LOG_RETENTION_DAYS, and ARTIFACT_RETENTION_DAYS. Logs and artifacts are always deleted along with their run.

现在0表示"永久保留"，适用于RUN_RETENTION_DAYS、LOG_RETENTION_DAYS和ARTIFACT_RETENTION_DAYS。日志和制品始终会随其运行记录一起删除。

⚠️ Git 2.25 or newer is required (#39131)

⚠️ 需要Git 2.25或更高版本(#39131)

本节标题："⚠️ 需要Git 2.25或更高版本(#39131)"

Gitea now refuses to start with a Git version older than 2.25.0. If you install Git yourself, check git --version before upgrading.

Gitea现在会拒绝启动低于2.25.0的Git版本。如果您自行安装Git，请在升级前检查git --version。

⚠️ Self-registration is off by default and [server] DOMAIN is ignored (#39400)

⚠️ 默认关闭自助注册且忽略[server] DOMAIN(#39400)

Section titled "⚠️ Self-registration is off by default and [server] DOMAIN is ignored (#39400)"

本节标题："⚠️ 默认关闭自助注册且忽略[server] DOMAIN(#39400)"

- Self-registration is now disabled unless [service] DISABLE_REGISTRATION = false is set explicitly.

- 自助注册现已默认关闭，除非明确设置[service] DISABLE_REGISTRATION = false。

- Gitea no longer reads [server] DOMAIN . The instance domain, including the default SSH domain, now comes fromROOT_URL , so setROOT_URL if you relied onDOMAIN .

- Gitea不再读取[server] DOMAIN。实例域名（包括默认SSH域名）现在来自ROOT_URL，因此如果您依赖DOMAIN请设置ROOT_URL。

Thank you to @wxiaoguang for contributing this change.

感谢@wxiaoguang贡献此变更。

⚠️ Actions workflows are evaluated more strictly (#39358)

⚠️ Actions工作流评估更严格(#39358)

Section titled "⚠️ Actions workflows are evaluated more strictly (#39358)"

本节标题："⚠️ Actions工作流评估更严格(#39358)"

- Job-level if: is now evaluated before the matrix is expanded and may only use thegithub ,gitea ,needs ,vars , andinputs contexts. Movematrix conditions tostrategy.matrix.include /exclude or to step-levelif: .

- 任务级if:现在会在矩阵展开前评估，且只能使用github、gitea、needs、vars和inputs上下文。请将矩阵条件移至strategy.matrix.include/exclude或步骤级if:。

- Matrix fail-fast is now enforced, so a failing job can cancel the remaining combinations. Setstrategy.fail-fast: false to let all of them finish.

- 矩阵快速失败现在会被强制执行，失败任务会取消剩余组合。设置strategy.fail-fast: false可让所有组合完成。

- Workflows in public repositories can no longer call reusable workflows from private repositories, and nested workflows can no longer exceed the caller's token permissions.

- 公开仓库的工作流不能再调用私有仓库的可重用工作流，且嵌套工作流不能再超过调用者的令牌权限。

感谢@silverwind贡献这些变更。
