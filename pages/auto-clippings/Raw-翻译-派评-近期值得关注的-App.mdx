Motrix 2.0：3 年后，「白月光」下载器更新了
- 平台：macOS / Windows / Linux
- 关键词：下载器
@Snow：在几年之前，Motrix 大概是可以被列入 macOS 装机必备清单的应用。它没有扰人的广告、没有骇人的劫持、没有烦人的资源占用，凭借 aria2 多协议、多线程下载能力以及简洁易上手的 UI 设计，Motrix 一度成为不少用户心中的「白月光」下载器。
不过自上架起，Motrix 的更新就算不上积极，大多每年更新一个小版本，1.8.19 版本后更是停更长达 3 年之久，以至于社区同好们都坐不住了，纷纷开发出了 Motrix Next、imfile 等衍生应用。加上近些年，网盘逐渐接管了普通用户的大文件传输需求，常规下载工具的存在感越来越低，就当大家快遗忘了这款应用时，开发者仿佛被人「夺舍」一般，在一周之内疯狂迭代十几版，而且不同于以往的小修小补，这次是实实在在从底层重新构建的 2.0 大版本更新。
开发者为 Motrix 2.0 起了一个新名字 Motrix Turbo，使用 Electron、React 和 TypeScript 重写，这其中最突出的变化就是把下载核心与用户界面「拆散」了。这意味着 Motrix 不再只是一个运行桌面端的下载应用，同一套下载能力完全可以独立运行在没有桌面环境的服务器上。
Motrix 2.0 首先引人注目的是直观的 UI 更新。全新的仪表盘由自定义卡片构成，你可以点击右上角的编辑按钮，调整卡片的展示和尺寸，不仅支持查看各项下载进程，还可以快速核查引擎状态、调整限速模式以及开关 UPnP 端口映射等。相比过去打开 Motrix 后直接面对堆砌的任务列表，新版仪表盘可以帮你更直观且高效地掌控下载时的资源调度。
原本藏在设置中的自定义 Trackers 获得了独立页面，你可以在这里快速订阅或屏蔽 Trackers 列表，并随时查看各个 Tracker 是否可用、屏蔽规则是否生效，管理上直观不少。
新版还加入了扩展生态，Motrix 目前提供了 3 款官方扩展，分别是文件名模板、网页内容提取和 URL 解析，后续你可以在应用官网的扩展商店或开源社区下载更多扩展，对于一个重新活跃起来的开源项目来说，这或许比单纯增加几个功能更有价值，如果哪天开发者又「神隐」了，社区大神们说不定还能借助扩展为它助力。
下载能力当然还是 Motrix 的核心，2.0 这次将重点放在了「断点续传」上。新版重新整理了下载核心，并加入任务恢复机制，无论是意外锁屏导致下载中断，还是退出应用重新打开，2.0 不会再像 1.x 那样完全摆烂，而是争取找回之前的下载任务，继续未完成的工作。
不过，Motrix 恢复成功与否很大程度上取决于下载服务器是否允许续传，像网盘或是临时下载链接你还是别指望它有什么黑科技可以「续命」。
对于「动手能力」更强的用户来说，真正 Turbo 的地方，是下载核心可以单拎出来用了。新版提供了 Headless Server，可以通过 Node.js 或 Docker 部署到家庭 NAS 或云端服务器上。你不用再为了维持下载的进程一直开着电脑，也不用担心转移场地会影响下载进程，直接让 NAS 这样常年运作的「牛马」承担下载任务即可，你可以通过 Web 页面随时随地添加下载、查看任务以及管理下载文件。
如果还想进一步折腾，2.0 版还提供了新的命令行工具，你可以通过 motrix add 等命令远程操作任意一台搭载 Motrix 2.0 的设备处理下载任务。这套 CLI 还专门为 AI Agent 留出了调用入口，配置完成后你可以让 AI 根据你的要求找到下载地址后，通过命令行直接把任务交给 NAS 执行，串起一套更高效的自动化流程。
Motrix 2.0 目前仍处于测试阶段，安装前请备份现有 Motrix 应用数据与下载文件。你可以在 应用官网 或 GitHub项目页免费下载 2.0 beta 版。
WebToApp：在手机上把网页变成 App
- 平台：Android
- 关键词：网页封装
@大大大K：不知道从什么时候开始，手机 App 动辄就飙升到几个 G，占用内存不说，实际上里面很多功能我们根本用不到。其实我们常用的工具站、社交网络等，其网页端本身就已经足够干净好用，只是用浏览器访问时标签一多就容易混乱，即使使用「添加至主屏幕」功能，本质上还是调用浏览器打开，如果网站还不支持 PWA，那体验真不算好。那为什么我们不直接把这些常用网页服务做成一个独立的 App 呢？
说到制作 App，或许你以为很困难，但有了 WebToApp，这一切就会变得很简单。不同于其他类似 App「把网页套进 WebView 里」的简单粗暴，也无需打开电脑配置复杂的开发编译环境，WebToApp 内置了一套功能完备的「标准应用外壳模板」（包含完整的浏览器内核、网络栈与扩展接口）。
当我们在手机里填好网址、设置好参数、配置好自定义选项后，WebToApp 会解析网页中的相关项目，连同你的配置导入到模板中快速生成一个独立的 APK，同时还能直接在手机端完成签名动作。
整个过程不需要你懂代码编译，也不用太多人工操作，更不用把数据上传到云端，所有操作都在手机本地一气呵成。当然了，如果网站支持 PWA，也可以直接套用 PWA 配置的同时获取独立 App 的使用体验。
在创建应用时，普通用户最常用的自然是「网页」类型，只需要输入目标网址、应用名称并挑选一个心仪的图标即可。但 WebToApp 远不止打包网页这么简单，如果你是一位喜欢折腾的玩机高手，WebToApp 支持多达 12 种类型的 App 构建，它甚至能在手机本地直接运行 Node.js、PHP、Python 甚至是打包 WordPress。
这意味着哪怕是一个依赖后端服务或者数据库的网站，也能被它直接打包成完全独立 App。
WebToApp 根据每种打包类型，提供了不同程度的自定义选项。比如在视觉和交互上，你可以配置全屏显示、自定义首屏、状态栏自适应取色等等；在浏览体验上，它支持拦截网站上的广告，或者启用桌面模式等等。配置完成后还能直接擎进行效果预览，确认整体符合预期后即可点击「构建 APK」完成打包与签名，并直接弹出系统的应用安装界面。
更棒的是，除了基础的打包和定制，WebToApp 的扩展能力也非常强大。它允许用户使用油猴脚本优化浏览体验，还直接打通了 Chrome Web Store 搜索通道，让你可以把桌面端的 MV3 浏览器扩展直接下载并装进 App 里。
在网络层面，除了系统自带的 WebView，你还可以按需切换为 GeckoView（也就是 Firefox 的内核），并获得 DoH、TLS JA3 指纹伪装等等一系列我甚至都看不懂的硬核特性。要是觉得海量的自定义配置太复杂，应用内还贴心地集成了 Agent，接入大模型后就可以像 Vibe Coding 一样直接说出你的需求，AI 就能自动调用 WebToApp 的能力替你完成参数调整与打包全流程。
整体而言，WebToApp 上能给高级玩家提供多种玩法、下能满足普通用户的轻量化 App 打包体验。无论你是想给常用的网页工具换个清爽独立的入口，还是想把复杂的脚本和程序打包成客户端，WebToApp 都能在一台 Android 手机上为你轻松搞定。
你可以在 GitHub 免费下载 WebToApp。
Algidy：追踪食物过期日
- 平台：Android
- 关键词：物品管理
@Peggy_：又到了采购日，你从超市购买了零食、牛奶、鸡蛋、蔬菜、肉类，到家后，一部分食物被你放到了冷藏室，一部分进入了冷冻室，还有一部分则凭借经验放在了厨房或储物室。然而，随着时间的推移，你发现总是能从各处搜索出来一堆过期的食物、酱料。Algidy 是一款想帮你解决上述问题的应用。
在 Algidy 中，我们可以看到多个物品存放区域，应用默认给出了冰箱、冷冻室、储物室，基本上涵盖了主要的食物的存储区域。我们可以根据自己家庭的存放习惯来设置食物的存放区域。除了根据存放位置分类外，我们还能自行在 Algidy 设置不同的食物分类，例如调料、水果、米面、零食等。
点击首页加号，便可以开始添加食物了，这里应用给出了两种添加方式，一种是扫描食品包装袋上的条形码，系统扫描后自动判定食品的名称，我扫描了部分身边的食品条形码，部分能准确识别，也存在无法识别的情况。对于无法通过扫描识别的食品，我们可以选择手动添加。无论是哪种添加方式，在详情页面，我们都能附加食品的图片，设置食品的存放位置和所属种类等。
随着食品的不断添加，我们便相当于有了一个掌心超市，应用会在首页直观展示出已添加食物的可食用时间还剩余多少，有效避免食物放置过期造成浪费。如果某种食物我们开封后食用完毕了，则可以点击相应图片，选择「已食用」，来达到归档效果。
Algidy 还支持搜索功能，方便我们查找相应的食物。在食品排序上，Algidy 支持按照食品过期时间排序、按照食品名称排序，也可以一键筛选出已过期食物，方便后续的清理。
目前 Algidy 的不足之处在于添加食品分类后，无法对标签进行删除或二次编辑，期待后续更新能补足相应功能。你可以通过 GitHub 发布界面下载体验 Algidy。
不空：钓鱼天气分析与鱼情记录
- 平台：iOS / iPadOS
- 关键词：钓鱼、鱼情分析
@ElijahLee：《不空》是由个人开发者推出的钓鱼应用，核心亮点是帮助钓鱼佬判断鱼情、查看天气、记录钓鱼数据并辅助提升下一次出钓。应用大小仅 10.8 MB，支持在 iPhone 和 iPad 上使用。
打开应用，即可感受到这款应用看起来非常专业。首页密集排列鱼情指数、鱼情分析、天气、未来爆护指数等等。
先别急，出钓前，先看「鱼情」指数。在应用上方，先选择目标鱼类后，应用会基于当前天气、地理位置和时间段内，判断分析各种鱼类的活跃度和咬钩概率，并提出「鱼情」指数，搭配显示停口、口稀、良好等标签提示。选择鱼种后，我们可以直观地判断现在这个天气下，目标鱼是不是好钓。
除了当天，应用还提供了未来 24 小时、未来 7 日鱼情分析，并且提供逐小时的气温、气压、风向、风力和降雨等信息，将这些天气变化与目标鱼的鱼情结合起来，即可判断哪天哪时最容易钓到鱼。如果你是周末才有时间钓鱼，可以提前比较未来几天的鱼情和推荐时段，再决定具体哪一天出门。
除了查看钓鱼天气之外，在应用中，我们可以把自己的钓鱼经历记录下来。在「出钓记录」中，我们可以记录每次的「上鱼」时刻或是「空军」情况。每次记录都支持选择钓点、时刻、鱼种和钓法，以及补充照片。应用会自动记录当时的天气，并且在今后出现相似天气时发出通知提醒。在「钓点地图」中，我们可以记录并查看自己的私有钓点，在应用内的地图中定位，即可快速添加。
这样积累一段时间之后，每个钓点都会形成一段历史数据，记录本身会反过来帮助判断下一次出钓。例如，你去年在某个位置钓鲫鱼时，恰好遇到气压下降、微风和小雨，鱼口很好。那么下一次遇到相似天气时，就可以回到自己的历史记录进行对照。
应用还提供了钓鱼百科、出钓记录统计、出钓习惯分析等功能。从版本历史来看，不空目前还处于快速迭代阶段。现在应用完全免费，你可以在 App Store (中区) 下载使用不空 app。
Moshi：在手机端继续调用你的 AI Agent
- 平台：iOS / Android
- 关键词：终端
@化学心情下2：随着 AI Agent 逐渐进入软件开发流程，不少开发工作已经可以直接在终端中完成：向 AI Agent 提出需求，由它完成编码、测试，再根据结果继续调整。
这种工作方式也带来了一个新的问题。AI Agent 可以长时间在电脑上运行，但人不可能始终守在电脑前。如果临时外出，能否直接通过手机查看任务进度、处理审批，并继续向电脑上的 AI Agent 发出指令？
部分 AI Agent 已经提供了类似的远程连接功能，但其它工具并不一定具备相同能力。Moshi 提供了另一种解决方案：通过手机连接 Mac 或 Linux 主机，并继续操作运行在其中的 AI Agent。
相比仅服务于特定 AI Agent 的远程功能，Moshi 的优势在于兼容范围较广。目前除了 Claude Code、Codex，也支持 Kimi Code、Pi、OpenCode 等工具。不过，由于需要同时处理远程终端和不同 AI Agent 的接入，Moshi 的初次配置也相对复杂一些。
Moshi 目前对 macOS 和 Linux 的支持较为完善。下面以已经安装 Homebrew 的 Mac 为例。
首先打开终端，安装 Moshi：
brew tap rjyo/moshi
brew trust rjyo/moshi
brew install moshi-hook
安装完成后，可以通过下面两条命令检查 Moshi 及其 Hook 工具是否正常工作：
moshi --help
moshi-hook --help
确认没有问题后，还需要安装 mosh 和 tmux：
brew install mosh tmux
接下来打开 macOS 的「远程登录」功能。进入「系统设置」&gt;「通用」&gt;「共享」&gt;「远程登录」，打开对应开关。Moshi 后续需要借助远程终端连接这台 Mac，因此这一步不可省略。
完成 Mac 端的基础配置后，可以在手机上安装 Moshi 客户端。启动应用并进入等待扫码的页面，然后回到 Mac，在终端中运行：
moshi-hook host setup
终端随后会显示用于配对的二维码，使用 iPhone 上的 Moshi 扫描即可完成设备配对。
接下来还需要为电脑上的 AI Agent 安装对应 Hook。在 Mac 终端中运行：
moshi-hook install
Moshi 会检查当前已经安装的 AI Coding Agent，并为受支持的工具写入相应的 Hook 配置。
例如，我的 Mac 上安装了 Codex 和 Kimi Code，Moshi 会分别为这两个工具创建 Hook。确认安装正常后，再将 Moshi Hook 设置为后台服务：
brew services start moshi-hook
至此，Mac 端的主要配置就完成了。重新回到 Moshi 手机客户端，此时应该已经可以看到刚刚配对的 Mac，并通过它建立远程连接。
后建立连接后，后续操作与直接使用终端已经比较接近。在 Moshi 的「连接」页面中选择对应设备，进入终端后切换到项目目录，例如：
cd ~/Projects/your-project
moshi .
codex
随后就可以直接从手机继续操作 Mac 上的 Codex 任务。
针对手机端的终端操作，Moshi 也做了一些适配，例如提供经过调整的键盘布局，并支持语音输入。在不方便使用手机键盘时，可以直接通过语音转写提示词，用于查看任务、继续发送指令或处理 AI Agent 发起的审批请求。
如果同时运行多个 AI Agent，Moshi 也可以管理多个会话。只要 Mac 保持联网且没有进入休眠状态，就可以继续查看不同 Agent 的执行情况。通过页面左上角的入口，还可以查看当前 AI Agent 的用量信息。
不过，进一步使用后会发现，Moshi 本身并没有完全解决远程访问的网络问题。如果 iPhone 和 Mac 不在同一个局域网中，手机可能无法直接连接家中的 Mac。
Moshi 给出的方案是借助 Tailscale 建立虚拟局域网，让两台设备即使处于不同网络环境，也能够继续通信。具体配置可以参考 Moshi 提供的相关教程，这里不再展开。
因此，从实际使用方式来看，Moshi 更接近一套针对 AI Agent 优化的移动终端和管理工具：它负责设备配对、Agent Hook、移动端交互和会话管理，但跨网络访问仍然需要 Tailscale 等工具配合。
如果只是希望从手机远程操作自己的 Mac，一些带有终端功能的成熟远程控制工具配置起来会更加直接；Moshi 的优势主要体现在 AI Agent 的适配和会话管理上。尤其是需要同时管理多种 AI Agent，或者连接 Linux VPS 等远程主机时，它提供了一套相对统一的手机端操作方式。
你可以在 App Store 或 Google Play 免费下载 Moshi ，Pro 订阅可用于解除部分会话限制。
Capture：为苹果全家桶用户而生的信息中转站
- 平台：iOS / iPadOS / watchOS / visionOS / macOS
- 关键词《文本处理、信息中转
@Vanilla：当我们在工作时突然想到一件待办事项、在浏览网页时看到一篇想稍后阅读的文章，或者走路时脑子里突然冒出一个想法，在采取行动前我们往往需要先做出一个判断，那就是用哪个工具来进行处理。这个时候，你需要考虑工具的平台适配性和支持的文件类型，还要决定把它存放在哪个列表，一套流程下来很容易就打断思路。
Capture 这款工具就是瞄准了这个很容易让人忽略的痛点，它解决这个问题的思路是先取消分类决策，让所有信息都进入 Capture 的收件箱，然后统一处理，分发到不同的专业工具上。
首先，Capture 可以让我们从不同的入口随时随地发起记录。在 iOS 客户端中，打开应用就会直接进入输入窗口，不需要新建文件，不需要找文件夹。Capture 支持创建文本、图片、链接、待办事项等不同类型的文件，都可以通过输入窗口直接新建。除了应用本体，我们还可以在第三方应用中通过共享菜单或者快捷指令来把内容导入到 Capture，也可以通过桌面小组件或者控制中心小组件来快速打开输入窗口。
在 macOS 平台上，我们可以为 Capture 的输入框绑定全局的键盘快捷键，可以从任意应用中呼出。桌面版的 Capture 也同样支持通过粘贴、小组件等方式来新增内容。在 Apple Watch 上，我们也可以通过口述来进行输入，Capture 会自动将语音转写成文本。
其次，Capture 中的内容在导出时支持针对性的格式输出。目前，Capture 已经对 59 个应用进行了适配，包括 Apple Notes、Bear、Things、Todoist、Google Calendar、Fantastical、Readwise、Readwise Reader、Instapaper、WhatsApp 等不同的类型。当导出到 Bear 时，Capture 可以预设标签、置顶和编辑状态；当导出到 Things 时，Capture 可以指定列表与标题；当导出到 Obsidian 时，Capture 可以配置 Vault 路径。
Capture 没有发明新的笔记格式，也没有建立宏大的知识管理方法。它只是把「打开应用—选择位置—填写信息—保存」压缩成一个动作，然后把判断推迟到更合适的时间。当然，如果我们只用 Capture 收集、不处理，它最终仍会变成另一个信息垃圾场。
