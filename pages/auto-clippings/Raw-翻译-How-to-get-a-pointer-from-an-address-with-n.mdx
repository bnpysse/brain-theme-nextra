【帖子标题】：如何从没有预先暴露证明来源的地址获取指针？

【帖子正文】：
在 Rust 中，创建来自地址的指针有三种方法：

使用严格证明 API 的

with_addr

使用类型转换或等效操作以及暴露证明来源 API 的

with_exposed_provenance

使用

without_provenance

第一种方法从现有指针推导出指针的证明来源；第二种方法尝试猜测先前已暴露的证明来源；第三种方法创建一个无法解引用的指针（以下是从文档中引用的内容）：

带有无证明来源指针的非零大小内存访问会导致未定义行为（UB）

这些方法都不能用于从没有任何预先暴露证明来源的原始地址创建可解引用的指针。这在跨 FFI 边界时可能会出现问题——例如，某些 C 函数接受与任何分配无关的指针，例如 Linux 的 libc 中的

brk

函数：

```
int brk(void *addr);
```

`brk()` 将数据段的末尾设置为由 `addr` 指定的值；当该值合理、系统有足够的内存且进程未超出其最大数据大小时，此操作会生效。

我不清楚是否可以在默认分配器旁边安全地使用

brk

，但假设您正在编写自己的分配器并希望使用

brk

来获取您分配的后备内存。在这种情况下，如何创建传递给

brk

的指针？

显然不能通过严格/暴露证明来源 API 创建该指针，因为该指针未绑定到任何分配，因此没有证明来源。唯一剩下的可能性是使用

without_provenance

，但如上文引用所示，在非零大小内存访问中这会导致未定义行为（UB）。我们假设

brk

不会访问该指针，但可以想象另一种实现会访问它。

无论如何，这不是最大的问题——如何为

brk

未返回的预留内存块创建指针，而分配器需要这样做？因为无法通过 FFI 将证明来源传递过来。显然不能使用严格证明来源 API，因为没有匹配新获得内存块证明来源的指针；也不能使用无证明来源的指针，因为我们实际上要写入此内存。暴露证明来源似乎也不会起作用（以下是从

with_exposed_provenance

文档中引用的内容）：

如果没有任何之前“已暴露”的证明来源可以解释返回指针的用途方式，则程序具有未定义行为。

所以我的问题是：如何获得没有现有指针的新分配内存的证明来源？
