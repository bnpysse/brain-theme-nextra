# 精华简报：AI 实验室间的千禧年难题“抢跑”争议

**来源**：Simon Willison（AI 实用工程化）  
**文章标题**：On the Navier–Stokes Millennium Prize Problem  
**日期**：2026年9月8日  
**链接**：[simonwillison.net/2026/Sep/8/on-navier-stokes/](https://simonwillison.net/2026/Sep/8/on-navier-stokes/)

---

## 一句话摘要

OpenAI 用未发布模型在 88 小时内解决千禧年大奖难题“纳维–斯托克斯存在性与光滑性”，但因其启动时间与竞争对手 Anthropic 合作团队的研究传闻高度重合，引发数据使用、学术优先权与企业竞争的多重争议。

---

## 核心事实与时间线

| 时间 | 事件 |
|---|---|
| 近一年前 | 纽约大学数学教授 Tristan Buckmaster 与 Anthropic 数学家 Levent Alpöge 开始合作研究纳维–斯托克斯问题，大量使用 Claude 和 OpenAI 的 Codex（主要是 GPT-5.6 Sol） |
| 8月15日 | Tristan 与 Levent 取得突破 |
| 9月1日 | OpenAI 听到“两个千禧年问题已被解决”的传闻，启动内部模型评估所有未解千禧年问题 |
| 9月5日 | OpenAI 的 AI 代理团队在启动约 88 小时后得出纳维–斯托克斯问题的解决方案 |
| 9月6日 | 完成 Lean 形式化验证（额外 17 小时，使用 GPT-6 Astra）；OpenAI 联系 Tristan 团队，提议联合发布并承认对方优先权 |
| 9月8日 | Tristan 方面公开发布自身结果与投诉；Simon Willison 撰写本文 |

**规模与成本**：  
- 所有千禧年问题尝试：**490 万条消息，约 3000 亿输出 token**；  
- 仅纳维–斯托克斯问题：**270 万条消息，约 1300 亿输出 token**；  
- 若按 GPT-6 Astra 公开 API 价格计算，3000 亿 token 约 **1500 万美元**（纳维–斯托克斯部分约 650 万美元）。

## 争议焦点

### 1. 时间线的“巧合”
Tristan 质疑 OpenAI 的首次提示请求是何时发出。据其转述，OpenAI 最初未直接回答，最终承认是在“过去几天、且相关信息已传到 OpenAI 之后”才启动。  
这意味着 OpenAI 可能在知晓“Anthropic 合作团队已解决重大问题”的传闻后，才针对性投入资源。

### 2. 用户数据是否被用于训练或访问
Tristan 直接询问 OpenAI：模型是否训练过或访问过他们存放在 Codex 中的草稿会话？  
- OpenAI 回应称“模型不会查找用户数据”；  
- 但对“是否用于训练”未作答复。  
OpenAI 官方声明则称：“没有通过任何方式看到他们的工作……没有访问特定用户数据”，但补充了一句关键保留：

&gt; **“虽然不太可能，但我们不能排除去标识化数据从其产品使用中帮助改进了我们的模型。”**

这正是争议的核心：即使用户数据未被直接访问，通过模型训练改进而间接吸收研究信息，仍无法被彻底排除。

### 3. 学术合著的政治
OpenAI 团队曾提出等待 Tristan 先发表，或由 Tristan 撰写关于 OpenAI 结果的论文，但明确表示：
&gt; **Levent 不会受邀担任共同作者，因为 OpenAI 与 Anthropic 存在竞争关系。**

企业竞争直接介入学术署名，进一步暴露 AI 实验室之间的竞合张力。

## Simon Willison 的解读

### 1. 这是一次典型的“抢跑”演示
Simon 认为，OpenAI 听到千禧年问题可能已被 LLM 解决后，将其视为展示最新模型能力的机会，**没有充分考虑“挖角”一个近一年来一直使用 OpenAI 自己模型工作的团队的观感**。

### 2. 数学界的“漏洞传闻效应”
他引用 Anil Madhavapeddy 关于计算机安全的观察：
&gt; “如今仅凭漏洞传闻就足以找到安全漏洞”。

如果知道某软件存在未修补漏洞，可以让 AI 代理去搜索。数学是否正进入同样阶段？  
**只要知道存在一个未发表的解法，就可能触发数百万美元的 LLM 投入，目标只是“率先到达”。**

### 3. 数据“用于改进模型”的透明度赤字
Simon 长期对 AI 实验室的表述感到沮丧：“我的数据用于改进模型性能”到底意味着什么？  
他提出两个旧假设：
- 如果 API 密钥意外进入 Codex 上下文，未来其他人询问时有多大几率“反刍”出我的密钥？（OpenAI 承认存在“反刍”问题并极力防止，但拒绝说明如何防止）
- 如果与 ChatGPT 头脑风暴公司新方向，六个月后信息有多大几率暴露给询问“公司 X 可能计划下一步”的竞争对手？

文章末尾提出新的假设性问题（原文在此截断），延续其对敏感研究通过 AI 工具被间接泄露或抢跑风险的担忧。

## 技术与商业分析

- **竞争激励扭曲学术优先权**：传统上，数学证明的优先权由发表时间决定。而 LLM 代理可以在极短时间内（88 小时）消耗巨额算力“追赶”，一旦“问题可解”的传闻流出，原研究团队可能被资金与算力优势方反超。  
- **数据使用政策的灰色地带**：OpenAI 的否认仅排除“直接访问特定用户数据”，但不排除“去标识化训练数据间接改进模型”。这种表述为竞争对手间接吸收用户研究思路保留了可能性，削弱用户对 AI 工具的信任。  
- **成本壁垒正在显现**：1500 万美元的公开 API 成本意味着，重大数学突破的 AI 路径可能被少数头部实验室垄断。学术团队即便长期研究，也可能在资源上被压过。  
- **安全与数学的趋同**：安全领域中“知道漏洞存在即可攻击”的逻辑，正在数学研究中重现。只要“已有解法”的消息泄露，拥有强 AI 的机构就能大规模搜索，且无需直接窃取数据。

---

## 关键启示

1. **敏感研究不要完全托管于单一 AI 供应商**：数据间接进入训练集的风险难以量化，多层次、跨供应商或本地化部署可能成为必要选择。  
2. **学术优先权需要新的保护机制**：仅依赖公开时间戳已不足够；可能需要预印本、链上时间戳或第三方存证来锁定“传闻出现前”的完整工作记录。  
3. **AI 实验室的数据政策需要更精确的披露**：必须明确“用于改进模型”是否包含训练、反刍风险如何控制、去标识化数据是否可能被用于与用户形成竞争关系的任务。  
4. **商业竞争正在侵蚀学术合作**：OpenAI 因 Levent 受雇于 Anthropic 而拒绝其共同署名，表明学术贡献与企业竞争之间的边界正变得模糊且工具化。
