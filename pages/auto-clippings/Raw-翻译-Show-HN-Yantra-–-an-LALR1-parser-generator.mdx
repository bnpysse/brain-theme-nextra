【文章标题】：Show HN: Yantra – an LALR(1) parser generator for C++

【文章标题】：展示HN：Yantra —— 一款面向C++的LALR(1)解析器生成工具

【文章正文】：

Yantra is a powerful compiler compiler and LALR(1) parser generator written in C++, with the following core features:

Yantra是一款用C++编写的强大编译器编译器和LALR(1)解析器生成工具，具有以下核心特性：

- An integrated lexer

- 集成词法分析器

- Built-in support for UNICODE/UTF8 input

- 内置UNICODE/UTF8输入支持

- Built-in AST builder

- 内置抽象语法树构建器

- Built-in AST walker(s)

- 内置抽象语法树遍历器

- Bottom-up parsing (being LALR), and top-down walking (traversal)

- 自底向上解析（LALR特性）与自顶向下遍历

- Multi-mode lexer, useful for implementing nested multi-line comments, etc.

- 多模式词法分析器，可用于实现嵌套多行注释等场景

- Lexer-driven (push-based) parser: reads input one character at a time and feeds tokens to the parser as they complete, useful for processing input as it arrives (e.g. from a socket).

- 词法分析器驱动（推送式）解析器：逐字符读取输入并在token完成时推送给解析器，适用于实时输入处理（如套接字数据）

- An optional amalgamated mode, where the entire parser is generated as a single cpp file, along with a full-featured main() function.

- 可选合并模式：将整个解析器生成单个cpp文件并包含完整main()函数

- Or, in non-amalgamated mode, the parser is generated as separate .hpp and .cpp files, ready to drop into an existing project.

- 非合并模式下则生成独立的.hpp和.cpp文件，便于集成到现有项目

The name Yantra is Sanskrit for machine, as in state machine in this context.

Yantra名称源自梵语"机器"，在此语境中指状态机。

Yantra has no dependencies beyond the C++ standard library, so building it is a plain CMake build:

Yantra除C++标准库外无其他依赖，构建过程为标准CMake流程：

git clone git@github.com:TantrixAuto/yantra.git

cd yantra

mkdir build && cd build

cmake ..

cmake --build .

This produces the ycc executable in bin/. Save a grammar file, hello.y:

这将生成bin/目录下的ycc可执行文件。保存语法文件hello.y：

start := stmts;

stmts := stmts stmt;

stmts := stmt;

stmt := ID;

ID := "[A-Za-z]+";

WS := "\s"!;

Then generate a parser from it:

然后生成解析器：

bin/ycc -c ascii -f hello.y -a

This writes hello.cpp (an amalgamated, self-contained parser with its own main()) and hello.log. Compile it with any C++23 compiler:

这将生成hello.cpp（包含独立main()的自包含解析器）和hello.log。使用任意C++23编译器编译：

# clang

clang++ --std=c++23 -o hello hello.cpp

# gcc

g++ --std=c++23 -o hello hello.cpp

# MSVC (cl.exe, from a Developer Command Prompt)

cl /std:c++23 /EHsc /nologo hello.cpp

The grammar above recognizes one or more whitespace-separated alphabetic words. -s &lt;string&gt; feeds that string directly to the parser as input (as opposed to -f &lt;filename&gt;, which reads from a file, or -i, which reads interactively from the console):

上述语法可识别一个或多个空格分隔的字母单词。-s &lt;字符串&gt;直接将该字符串作为解析器输入（区别于从文件读取的-f &lt;文件名&gt;或从控制台交互读取的-i）：

# succeeds silently

$ ./hello -s "hello world"

$ echo $?

0

# -t1 prints the parsed AST

$ ./hello -s "hello world" -t1

0:start_1(1:stmts_1(2:stmts_2(3:stmt_1(4:ID(hello))) 2:stmt_1(3:ID(world))) 1:_tEND())

# fails: ID only matches letters, "123" isn't valid input for this grammar

$ ./hello -s "hello 123"

s1-err:?a1.in(001,007):TOKEN_ERROR&#123;&#123;token: &#125;&#125;

hello 123

$ echo $?

1

Yantra parses the entire input into an AST first, then walks it top-down calling your semantic actions, unlike most parser generators, where actions run bottom-up as each rule is reduced. That ordering is what lets a parent rule's action run before its children are visited. Save this as calc.y:

Yantra会先将完整输入解析为AST，然后自顶向下遍历并调用语义动作，这与多数解析器生成器在规则归约时自底向上执行动作不同。这种顺序使得父规则动作能在访问子节点前执行。将以下内容保存为calc.y：

%class Calculator;

start := expr;

expr := expr(a) PLUS expr(b)

%&#123;

std::cout &lt;&lt; "Adding" &lt;&lt; std::endl;

%&#125;

expr := NUMBER(N)

%&#123;

std::cout &lt;&lt; "Number: " &lt;&lt; N.text &lt;&lt; std::endl;

%&#125;

NUMBER := "\d+";

PLUS := "\+";

WS := "\s+"!;

Generate and compile it the same way as above (bin/ycc -c ascii -f calc.y -a, then any of the three compiler commands), then run it:

按前述方式生成和编译（bin/ycc -c ascii -f calc.y -a，再使用三种编译器命令之一），然后运行：

$ ./calc -s "1 + 2 + 3"

Adding

Number: 1

Adding

Number: 2

Number: 3

1 + 2 + 3 parses left-associatively as (1 + 2) + 3. So the outer Adding, the root of the tree, prints first, followed by its left child (Number: 1) and then its right child, which is itself another Adding node with its own two children. A hand-written recursive-descent or bottom-up parser would have to build extra AST classes and a separate walking pass to get this ordering. Here it falls out of the grammar directly.

表达式1 + 2 + 3按左结合性解析为(1 + 2) + 3。因此最外层的Adding（树根）最先打印，接着是其左子节点（Number: 1），然后是其右子节点（另一个包含两个子节点的Adding节点）。若手动编写递归下降或自底向上解析器，需额外构建AST类和独立遍历阶段才能实现此顺序，而Yantra直接从语法中自然获得该特性。

- vs. Bison / Yacc / Lemon (the classic LALR(1) family):

- 对比Bison/Yacc/Lemon（经典LALR(1)家族）：

- Lemon, from SQLite, is Yantra's direct stated inspiration.

- SQLite的Lemon是Yantra直接声明的灵感来源

- These run semantic actions during parsing, as each rule reduces, bottom-up.

- 它们在解析时自底向上执行语义动作（随规则归约）

- Yantra always builds the full AST first, then walks it top-down in a separate pass, so a parent rule's action can run before its children are visited.

- Yantra总是先构建完整AST，再单独自顶向下遍历，使父规则动作先于子节点访问执行

- A single grammar can also define more than one walker (e.g. one that emits C++, another that emits Java, from the same parse).

- 单个语法可定义多个遍历器（如从同一解析结果分别生成C++和Java）

- Getting either of those out of the Bison family means hand-building your own AST and walker on top.

- 在Bison家族中实现这些需手动构建AST和遍历器

- vs. ANTLR:

- 对比ANTLR：

- ANTLR walks a fully-built parse tree too, but that comes for free from its LL(*) algorithm, which already builds the tree top-down as it parses.

- ANTLR也遍历完整语法树，但这得益于其LL(*)算法在解析时即自顶向下构建树

- Yantra gets the same top-down walk out of LALR(1), a bottom-up algorithm with no natural "whole tree exists yet" moment during parsing, while keeping LALR(1)'s time and space efficiency over adaptive LL(*).

- Yantra在LALR(1)（自底向上算法，解析过程中不存在"完整树已构建"的天然节点）中实现相同自顶向下遍历，同时保持LALR(1)相对于自适应LL(*)的时空效率

- Beyond that, Yantra targets C++ only (ANTLR generates for many languages) and ships its own integrated lexer with mode-stack support instead of a separate lexer generator.

- 此外，Yantra仅针对C++（ANTLR支持多语言），并内置支持模式栈的词法分析器而非独立生成器

- ANTLR's own generator tool is Java, so using it from a C++ project means adding a JVM to the build toolchain just to run the generator. Yantra is a native C++ executable with no such dependency.

- ANTLR生成工具本身基于Java，在C++项目中使用需为生成环节引入JVM依赖，而Yantra是原生C++可执行文件无此依赖
