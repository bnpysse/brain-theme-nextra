# 📰 The Job Search Automation workflow - V2

**来源**: The Wondrous Mind of Dereck Bearsong
**链接**: https://dereckbearsong.substack.com/p/the-job-search-automation-workflow

## 📝 核心主旨 (TL;DR)
作者分享了将其求职自动化工作流从低代码工具 n8n 迁移至 Python 的实践经验，指出 Python 在解决 AI Agent 节点输出不稳定和调试受限问题上具有显著优势；同时详细拆解了基于 Python 构建的包含数据清洗、AI 多维评分、人工复核及自动化生成定制简历/求职信的端到端求职 Pipeline，并客观分析了当前 AI 自动化落地中面临的评分一致性、数据抓取及 Prompt 调优等挑战。

## 💡 关键知识点 / 核心观点
1. **低代码自动化与纯代码的权衡 (n8n vs Python)**
   n8n 适合快速搭建原型和处理简单数据转换，但其内置的 AI Agent 节点存在输出不一致、错误处理控制弱、节点硬编码导致黑盒调试困难等瓶颈。迁移到 Python 虽然增加了编码工作量（“弄脏手”），但提供了细粒度的流程控制、直接的代码级断点调试能力，是构建复杂且对稳定性要求高的 AI 工作流的更优解。
2. **“AI 初筛 + 人工复核”的漏斗式 Pipeline 设计**
   工作流并未追求 100% 无人值守，而是设计了合理的人机协同机制：首先通过 AI 对“职位标题”进行初步匹配打分；接着**人工介入**审核并标记跳过项；然后针对高分职位抓取职位描述（JD）进行深度 AI 匹配打分；最后仅对双项评分均 &gt;80 分的职位触发简历和求职信的生成。这种漏斗设计有效过滤了 AI 幻觉和误判，提高了最终投递的质量。
3. **基于 LLM 的多维度匹配与内容生成逻辑**
   系统利用 AI 进行两层核心对比：一是将“目标职位标题”与“用户历史职位/核心技能”对比打分；二是将“职位描述(JD)”与“用户简历”对比打分，并要求 AI 输出评分推理依据（Reasoning）。在最终环节，利用 AI 针对高匹配度职位定向重写简历（Resume rewriter）和生成求职信（Cover letter writer）。
4. **AI 自动化工作流的现实痛点与调优方向**
   作者指出了当前 V2 版本的局限性，反映了 AI 工程化落地的普遍难题：
   - **一致性问题**：AI 评分标准不稳定，重复运行同一任务时分数波动较大。
   - **数据获取瓶颈**：职位描述（JD）的抓取已实现自动化，但初始职位列表的获取仍需手动网页抓取。
   - **Query 优化**：初始搜索查询（Query）不够精准，导致标题审查阶段产生过多无效数据。
   - **Prompt 工程挑战**：简历重写 Prompt 已基本达标，但求职信生成缺乏优秀的指导原则，Prompt 调优困难，目前只能妥协于“足够好（Good enough）”的状态。

## 🏷️ 提及的重要概念/公司/模型
- **工具与框架**: n8n (开源工作流自动化), Python, JavaScript, React, NodeJS, Google Docs (电子表格), Jira, Linux, Windows
- **公司**: Atlassian (作者前雇主)
- **AI 与技术概念**: AI Agent node (AI 代理节点), Web scraping (网页抓取/爬虫), Prompt tuning (提示词调优), Data deduplication (数据去重), LLM (大语言模型，隐含于 AI 比较与生成逻辑中)
- **业务与流程概念**: Job Search Automation (求职自动化), Pipeline (工作流管道), Resume rewriter (简历重写器), Cover letter writer (求职信生成器)
