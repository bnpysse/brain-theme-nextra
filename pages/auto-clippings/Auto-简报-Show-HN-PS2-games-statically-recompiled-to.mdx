# 精华简报：PS2 游戏静态重编译至 WebAssembly

## 项目概述

该项目（ps2-web-recomp）展示了一种无需模拟器即可在浏览器中运行 PlayStation 2 游戏的技术路径。其核心方法是将 PS2 的 Emotion Engine（情感引擎）机器码**提前（AOT）翻译为 C++**，再编译为 WebAssembly，并与重新实现的 PS2 操作系统和硬件层链接，最终通过 **WebGPU** 完成图形绘制。

## 已验证成果

- **《GT赛车4》**：作为系统上要求最高的游戏之一，已实现从启动、开场动画、菜单到比赛全流程可玩，含音乐、音效及浏览器内记忆卡存档。在 Chrome 浏览器、笔记本集成显卡上，以 PS2 两倍分辨率运行 PAL 版本，比赛场景达到全速 50 FPS。

- **《战神II》**：无需任何游戏专属代码即通过同一套流程运行，过程中发现并修复了重编译器与向量单元时序的两个 bug，并补齐了 I/O 处理器缺失功能。在 PS2 原生分辨率下，激烈战斗场景稳定 60 FPS；两倍分辨率下为 48–60 FPS（受集成显卡性能限制）。

## 技术亮点

### 1. 静态重编译（eerecomp）

- 通过跟踪控制流识别函数，以 16 KiB 客户代码为单位生成 C++。

- 完整保留 R5900 架构特性：128 位寄存器、多媒体指令、分支延迟槽、非 IEEE 浮点行为（无无穷大/非规格化数、舍入规则不同）、向量单元 0 协处理器模式。

- 单元间跳转优化为尾调用，线程切换通过展开宿主栈实现，无需为每个客户线程维护独立栈。

### 2. 轻量级 PS2 内核

- EE 侧（主 CPU）操作系统通过高级模拟实现：线程、信号量、DMA/垂直空白中断、警报、SIF 通道。

- IOP（I/O 处理器）侧运行游戏自带的 IRX 模块（声音驱动、光盘流、控制器/记忆卡驱动），其 R3000 CPU 使用解释器，而 IOP 内核与库函数用 C++ 重写。

- 光盘数据通过 HTTP Range 请求按需读取，仅需预先下载可执行文件。

### 3. 向量单元（VU1）精确模拟

- 游戏上传的微程序以**位精确**的 PS2 浮点数学运行，并模拟 MAC、状态、裁剪标志的流水线延迟（游戏代码依赖这些时序）。

- 测试中遇到的微程序提前编译为 SIMD C++；首次遇到的新微程序可即时翻译为 WebAssembly 模块（每个仅需几毫秒）。

### 4. 图形子系统（Graphics Synthesizer）

- 4 MB 显存以原生 swizzled 布局驻留 GPU，绘制由 WebGPU 计算着色器完成。

- 三角形分箱到瓦片，严格遵循 GS 的纹理、调色板、Alpha 混合、深度与目标 Alpha 测试规则。

- 支持 1x/2x/3x 内部分辨率；保留软件光栅化器作为 GPU 输出的参考基准。

### 5. 多线程架构

- 模拟主循环运行于 worker 线程；VU1 拥有独立 worker 以模拟主机并行行为；GS 命令通过环形缓冲区传递至持有 WebGPU 设备的页面线程。

## 商业模式与分发

- 仓库**不包含任何游戏数据**，用户需提供自己拥有的游戏光盘镜像。

- 本地脚本将镜像转换为可在浏览器中运行的网页，兼顾版权合规与用户自主性。

## 分析点评

- **技术意义**：该项目展示了静态重编译在复杂主机模拟领域的可行性，相比动态二进制翻译（如模拟器），可显著降低运行时开销，并利用 WebAssembly 实现跨平台高性能执行。

- **性能表现**：在集成显卡上即可达到原机全速甚至更高分辨率，说明优化空间巨大，未来有望在低端设备上流畅运行 PS2 游戏。

- **潜在影响**：为老旧游戏主机的 Web 化保存与分发提供了新范式；若结合云游戏或 PWA 技术，可能催生“无需下载、即点即玩”的经典游戏平台。

- **风险与挑战**：目前仅验证两款游戏，通用性仍需更多测试；WebGPU 的兼容性、浏览器内存限制、以及复杂游戏的边缘情况（如更多 IOP 外设）是后续主要障碍。
