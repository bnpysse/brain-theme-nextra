# 精华简报｜旧版 Edge 的怀旧：技术理想如何被商业理性终结

**来源**：少数派 sspai  
**文章链接**：https://sspai.com/post/113295  
**文章性质**：产品体验回顾 / 技术评论，作者个人观点  
**核心议题**：在 Edge Legacy（EdgeHTML）停止支持五周年之际，作者从技术体验与浏览器内核多样性出发，重新审视旧版 Edge 的独特价值与失败原因。

---

## 一、文章核心命题

作者并非单纯怀旧，而是提出一个技术与商业之间的张力：

&gt; 旧版 Edge（EdgeHTML）在平滑滚动、EPUB 阅读、字体渲染、省电等方面有至今仍未被完全超越的体验；但它因为与 Windows 强绑定、迭代缓慢、生态薄弱而失败。微软转向 Chromium 是“商业上无比正确的决定”，却进一步加剧了浏览器内核单一化。

文章最后以“我为什么要给 Edge 招魂”为转折，将问题从产品体验上升到浏览器引擎多样性、互联网治理与技术路线选择的层面。

---

## 二、关键背景与时间线

| 时间 | 事件 |
|---|---|
| 2014.11.11 | 微软在 Windows 10 预览版推出 “living Edge document mode”，被视为 EdgeHTML 思想起点 |
| 2015.1 | 公开 Project Spartan 浏览器 |
| 2015.4.29 | 正式命名为 Microsoft Edge |
| 2015.7.29 | Edge 随 Windows 10 正式发布 |
| 2015–2018 | EdgeHTML 从 12 演进到 18，随 Windows 10 功能更新交付 |
| 2019 | The Verge 采访指出企业延迟部署 Windows 功能更新，导致 Edge 长期落后 |
| 2021.3.9 | Edge Legacy 停止支持 |
| 2026.3.9 | 本文纪念的停止支持五周年 |

文中特别说明：EdgeHTML 与 MSHTML 引擎并未彻底消失，它们仍作为 Windows 组件为 UWP 应用提供网页渲染支持。

---

## 三、技术分析：旧 Edge 的差异化遗产

旧 Edge 的体验优势并非营销话术，而是来自与 Windows 系统层的深度集成。

### 1. 平滑滚动：当时“次世代”的滚动体验

作者认为旧 Edge 的滚动体验直到今天仍未被 Chrome、甚至 Edge Chromium 完全复制。其核心在于：

- 不仅把滚轮输入转化为固定距离位移，而是加入**持续一段时间的速度曲线**；
- 连续滚动时，新输入会修改正在进行的动画，产生**有惯性但仍跟手**的效果；
- 根据滚动容器尺寸计算滚动量，同一滚轮操作在大页面区域中移动更远；
- 与 Windows 的 **DirectComposition / Direct Manipulation** 深度结合；
- 滚动为异步处理，即使主线程重任务，滚动也不易卡顿；
- 旧 Edge 是唯一支持**侧边栏异步滚动**的浏览器。

### 2. EPUB 阅读器：接近完整阅读器的浏览器内建体验

- 页面渲染为**可重排的分页**，不是基于 shadowroot 的方案；
- 翻页性能优雅，优于 Calibre 等独立阅读器；
- 支持全部页面墨迹批注、圈画；
- 作者认为这是“最好用的 EPUB 阅读器”，直到最后版本才被移除。

### 3. 字体渲染：更接近 Windows 本机效果

- 旧 Edge 使用 Windows 的 **DirectWrite** 渲染字体；
- Chromium 当时使用 Skia，硬编码设置导致文本比 Windows 系统默认设置偏细，CJK 字符差异尤其明显；
- 直到 Chrome 132 之后，Chromium 才接受 Edge 团队 patch，提供更接近旧 Edge 的字体渲染体验。

### 4. 系统级集成与省电

- 广泛使用 Windows 已有 API：Media Foundation、Windows Imaging Component、DirectWrite；
- PDF 使用 WinRT PDF 渲染器；
- 因此性能与功耗表现优秀，但也导致与 Windows 强绑定。

### 5. 兼容性策略：用现实网站驱动修复

- 新 UA 字符串，主动放弃 IE 兼容模式；
- 优先实现其他主流浏览器和现实网站共同使用的 API，而非盲目追求标准清单；
- 利用 Bing 抓取大量 URL，查找高频相同代码，优先解决实际兼容问题。

---

## 四、失败根因：结构性问题而非单点缺陷

作者将旧 Edge 的失败归结为几层结构性问题：

### 1. 发版节奏与 Windows 更新耦合

旧 Edge 的主要平台功能随 Windows 10 半年功能更新交付，无法像 Chrome/Firefox 一样独立快速更新。企业延迟部署 Windows 功能更新，会直接导致 Edge 长期落后。

### 2. UWP 平台拖累

Edge 基于 UWP 构建，但 UWP 本身并非成熟的开发平台。Edge 需要等待 UWP 平台修复 bug 或添加新特性才能推进，显著拖慢迭代速度。

### 3. 扩展生态薄弱

扩展功能并非第一天可用，导致浏览器扩展社区不成熟；开发者测试意愿低，又反过来降低用户规模和兼容性，形成恶性循环。

### 4. 用户规模不足 → 生态回报偏低

用户量一直不高，开发者不再对 Edge 做测试验证。最终，维护独立内核的成本远超生态回报。

### 5. 强绑定限制市场覆盖

深度依赖 Windows API 使旧 Edge 无法移植到 Windows 7 或其他操作系统，限制了潜在用户群，也为最终死亡埋下伏笔。

---

## 五、商业决策解读：转向 Chromium 为何是必然？

作者承认，微软放弃 EdgeHTML 是“商业上无比正确的决定”。

转向 Chromium 后：

- 微软不必独自承担 Web 平台底层成本；
- 可集中资源在浏览器 UI、企业管理、Windows 集成、隐私与服务上竞争；
- 解决兼容性和独立发版速度问题；
- 实现跨平台覆盖。

从商业理性看，这是把“内核维护”这种高固定成本、低差异化回报的层外包给 Chromium 生态，从而转向更高层的产品竞争。

但代价也清晰：**浏览器内核多样性进一步萎缩，Chromium 成为事实标准，Firefox 被边缘化。**

---

## 六、内核多样性：技术理想与治理担忧

文中引用了微软早期拒绝 WebKit 的理由：

&gt; “Web 建立在多个独立但可互操作的实现之上，我们必须抵制互联网出现单一化趋势。”

Mozilla 也表达了类似观点：

&gt; 独立浏览器引擎可防止技术经济力量过度集中，避免网络发展方向偏离公共利益，服务于少数大型平台的利益。

作者立场非常明确：

&gt; 独立的浏览器内核本身就有价值。即使 Safari、Firefox 各有缺点，我们仍然需要它们存在。如果只有 Chromium，Google 将能够亲自管理甚至亲自禁止整个互联网上的内容。

但现实是：从份额看，所谓“三分天下”只是形式上存在，Chromium 已经在事实上统治 Web。作者的怀旧因此带有一种技术治理层面的失落感。

---

## 七、对产品与技术决策者的启示

1. **深度平台集成是双刃剑**  
   与系统绑定可以带来极致体验，但会牺牲独立迭代、跨平台和生态灵活性。追求技术峰值体验时，必须评估结构性代价。

2. **局部体验优势难以对抗生态网络效应**  
   平滑滚动、EPUB、字体渲染虽然领先，但浏览器真正的护城河是扩展生态、开发者适配、发版速度与用户规模。单点体验很难逆转平台级竞争。

3. **自研基础设施需要规模承载**  
   自研渲染引擎的维护成本巨大，必须有足够用户份额或战略理由支撑。否则即使技术路线正确，商业上也不可持续。

4. **标准多样性与商业效率存在深层矛盾**  
   商业理性倾向于共享底层、避免重复建设；但行业治理需要保留独立实现作为制衡。这个矛盾目前没有简单答案。

5. **继承与淘汰可以同时发生**  
   旧 Edge 虽然死了，但其字体渲染 patch、系统集成思想仍以片段形式残存在 Chromium 和 Windows 组件中。技术路线的价值未必完全消失，而是被部分吸收。

---

## 八、结论

旧 Edge 的“招魂”，本质上是怀念一种**技术差异化路线**在 Windows 深度集成下曾经达到的体验高度。它证明了极致体验可以来自系统级集成，但也证明了浏览器竞争早已不只是内核技术优劣，更是生态、迭代速度与商业模式的综合竞争。

Edge 的遗产以 patch、API 与集成思想的形式活了下来；而浏览器内核多样性的理想，则更多成为行业治理层面的一则警示。旧 Edge 的失败，是一个技术理想被商业理性终结，但局部体验仍被长久记住的故事。

## 附：核心术语表

| 术语 | 含义 |
|---|---|
| MSHTML | Internet Explorer 使用的 HTML 渲染引擎，EdgeHTML 从它分叉 |
| EdgeHTML | 旧版 Edge 使用的 HTML、CSS、DOM、布局与渲染平台 |
| Chakra | IE9 以后及旧版 Edge 使用的 JavaScript 引擎 |
| Edge Legacy | 2015 年随 Windows 10 发布、基于 EdgeHTML/Chakra 的旧版 Edge |
| Edge Chromium | 基于 Chromium 的现代 Edge，使用 Blink 和 V8 |
| DirectWrite / DirectComposition / Direct Manipulation | Windows 图形、合成与输入 API，旧 Edge 借此实现高质量体验 |
