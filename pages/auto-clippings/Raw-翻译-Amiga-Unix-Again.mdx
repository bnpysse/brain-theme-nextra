Amiga Unix, again
再探Amiga Unix

Amiga Unix â Amix â was Commodore's System V Release 4 for the Amiga: shipped in 1990â92 for the A2500UX and A3000UX, then left where it stood. amigaux.org is an unofficial community project that picks it up again: Amix on 68040 and 68060 machines and on today's accelerator hardware, with a modern toolchain, a package manager, and drivers for cards that never had any. The work is done in the open, and written down as it happens in the grimoire.
Amiga Unix（Amix）是Commodore为Amiga开发的System V Release 4系统：1990-92年间随A2500UX和A3000UX发售，随后便被搁置。amigaux.org作为非官方社区项目重启了这一系统：让Amix在68040/68060机器和现代加速硬件上运行，配备现代化工具链、包管理器，并为从未获得驱动的显卡编写驱动。所有开发工作公开进行，并实时记录在grimoire手册中。

Soon: install it yourself
即将到来：自主安装时代

The install medium boots from floppy and CD-ROM on real hardware â floppy image and ISO under emulation â and takes care of the whole installation, interactively or unattended. With supported hardware, getting Amix onto a machine comes down to following the prompts. The classic tape install follows later.
安装介质支持实机从软盘和CD-ROM启动（模拟环境下使用软盘镜像和ISO文件），可完成交互式或无人值守的全自动安装。在兼容硬件上，只需按照提示即可完成Amix部署。传统的磁带安装方案后续推出。

From there the network takes over: apkg installs packages straight from pkg.amigaux.org â grep, gzip, less, patch and zlib to start with, and more GNU and BSD tools as they are built and tested.
随后网络接管工作：apkg包管理器可直接从pkg.amigaux.org获取软件包——初始包含grep、gzip、less、patch和zlib，更多GNU与BSD工具将在测试通过后陆续加入。

How it's built
构建方式：
Part of this work is done with generative AI in the loop â models reading the old kernels in binary, as no source is available, and writing drivers and notes â with people setting direction, reviewing every change and testing on real hardware, where it either boots or it doesn't. Other parts are done the classic way. The grimoire records both, confidence-tagged, so you can see what is verified and what is still a guess.
部分工作采用生成式AI辅助——在没有源代码的情况下，模型直接读取二进制旧内核来编写驱动和注释，由人类开发者把控方向、审查每个改动并在实机测试（成败立现）。其余部分采用传统方式开发。grimoire手册对两者均做信心度标记，区分已验证内容和待确认推测。
