# 精华简报：Ryan Carson 一个月花 2 万美元在 Devin 上学到了什么

**来源**：Lenny's Newsletter（产品与增长深度）  
**嘉宾**：Ryan Carson（Untangle 独立创始人，五次创业者）  
**对话者**：Claire Vo（ChatPRD 创始人）  
**核心主题**：独立创始人如何将 AI 智能体（尤其是 Devin）深度整合到产品开发、客户成功与运营中，以及由此产生的管理方法、工具选择与产品哲学。

---

## 一、背景与动机

Ryan Carson 是五次创业者，曾联合创办在线编程教育平台 Treehouse，目前是 Untangle 的独立创始人——一个面向家庭律师事务所的 B2B SaaS 平台。他每月在 AI 工具上投入约 **2 万美元**，其中 Devin 是核心支出。他在 X 上实时分享独立创始人旅程，包括每月实际 AI 花费。

他的实践代表了一种极端但极具参考价值的路径：**一个人 + 多个 AI 智能体 = 一支虚拟团队**。

---

## 二、核心发现与关键要点

### 1. 用极简系统管理 15 个并发 Devin 智能体

Ryan 同时管理 **15 个并发 Devin 智能体**，但他不使用任何复杂仪表盘，而是：

- **文件夹系统**：每个智能体对应一个文件夹，存放上下文、任务和产出。
- **一张纸**：用实体纸质清单跟踪 P0 优先级任务（类似 Ugmonk 实体待办系统）。

**原因**：降低认知负担，避免决策疲劳。当智能体数量增多时，仪表盘本身会成为新的管理负担。极简物理跟踪让他能快速判断“现在该关注什么”。

&gt; 对比 Claire 的方法：Claire 更倾向于用自动化评分工具（如 Merge Mommy）来辅助决策，而 Ryan 选择用最原始的方式保持对全局的掌控。

---

### 2. Watchdog 操作手册：替代客户成功团队

Ryan 构建了一套名为 **Watchdog** 的系统，用于跨每个律所账户的主动监控，实质上替代了传统客户成功团队的功能。

- 结合 **Sentry** 等错误监控工具，Devin 智能体持续监控账户健康状态、异常和潜在问题。
- 当检测到问题时，智能体可以主动介入或通知 Ryan，实现 **7×24 小时被动式客户成功**。

**意义**：独立创始人无需雇佣客户成功团队，就能为 B2B 客户提供主动式服务。

---

### 3. LAN PR 技能：无 QA 团队每天处理 40 个 PR

Ryan 每天要处理约 **40 个 PR**，但没有 QA 团队审查任何一个。他依靠一套名为 **LAN PR** 的技能实现闭环：

- **审查循环**：智能体自动审查代码变更。
- **视频演示**：生成变更的可视化演示，便于快速理解。
- **自动合并**：低风险 PR 自动合并，高风险 PR 标记人工处理。

**对比**：Claire 的 **Merge Mommy**（基于 Eve 智能体，部署在 Vercel）用于 PR 风险评分，两者思路相似——用 AI 替代人工代码审查，但 Ryan 的 LAN PR 更强调端到端自动化。

---

### 4. 工具选择：何时用 Codex、Devin、Claude Code

Ryan 几乎完全放弃了本地智能体，原因在于**云端智能体更适合并发和异步任务**。但他仍在一种特定场景下使用 Codex：

| 工具 | 使用场景 |
|------|----------|
| **Devin** | 云端并发智能体、运营任务、Watchdog 监控、PR 处理 |
| **Codex** | 从 Claude Design 生成的 Markdown 规格构建真实产品 |
| **Claude Code** | 本地 EA 工具（在 Mac Mini 上运行） |
| **Cursor** | 代码编辑 |
| **OpenClaw** | 基于 Claude 的桌面客户端，用于 Polly（EA 工具） |

**关键判断**：本地智能体在并发和异步场景下效率不足，云端智能体可以同时处理多个任务且不阻塞主流程。Codex 的保留场景是**从设计规格到真实产品的构建**，因为它在代码生成质量上表现更优。

---

### 5. 设计工作流：Claude Design + Codex

Ryan 和 Claire 都在使用同一套设计工作流：

1. **Claude Design**：生成 Markdown 格式的设计规格说明。
2. **Codex**：根据规格说明构建真实产品。

**优势**：将设计意图与代码实现解耦，确保 AI 生成的代码符合预期，同时保留人类对设计方向的把控。

---

### 6. 真实客户反馈改变产品方向

Ryan 提到，当他**离开电脑、去见一位真实客户**后，发现产品方向需要重大调整——转向**离婚领域的 PMF**，并推动 B2B 增长。

**核心观点**：**更多 AI 产出不等于更好的产品**。AI 可以快速生成大量代码和功能，但如果方向错误，产出越多浪费越大。应该优化的是**产品成果和客户价值**，而非 PR 数量或 token 消耗。

---

### 7. 招聘第一位工程师：跳过传统面试

Ryan 招聘第一位工程师时，**没有进行任何电话筛选或面试**。他采用了一种非传统的方式（可能通过实际项目合作或试用期评估），直接考察候选人在真实工作场景中的表现。

**启示**：在 AI 辅助下，独立创始人可以更灵活地评估人才，传统面试流程可能不再是必要条件。

---

## 三、对创业者与团队的启示

1. **AI 产出是手段，不是目标**：优化客户价值和产品成果，而非追求更多 PR 或 token 消耗。
2. **极简管理智能体**：当智能体数量增多时，简单工具（文件夹 + 纸）可能比复杂仪表盘更有效。
3. **云端智能体优先**：对于并发、异步任务，云端智能体优于本地智能体。
4. **自动化客户成功**：用 AI 监控替代人工客户成功团队，独立创始人也能提供企业级服务。
5. **设计规格先行**：用 Claude Design 生成规格，再用 Codex 构建，确保 AI 代码质量可控。
6. **真实客户反馈不可替代**：AI 无法替代你与真实客户的对话，方向性决策必须来自现场。

---

## 四、工具清单速览

- **Devin (Cognition)**：云端 AI 智能体，核心支出
- **Codex (OpenAI)**：从设计规格构建产品
- **Claude Code / Claude Design (Anthropic)**：本地 EA 工具 + 设计规格生成
- **OpenClaw**：基于 Claude 的桌面客户端
- **Cursor**：代码编辑器
- **BugBot**：Devin 内置 PR 审查
- **Sentry**：错误监控（Watchdog 集成）
- **Ugmonk**：实体待办系统
- **Merge Mommy**：Claire 的 PR 风险评分智能体

---

## 五、结论

Ryan Carson 的实践展示了独立创始人如何用 AI 智能体扩展能力边界：一个人管理 15 个并发智能体、每天处理 40 个 PR、替代客户成功团队、跳过传统招聘流程。但他的核心经验并非“如何用 AI 做更多”，而是**“如何用 AI 做对的事”**——聚焦客户价值、保持极简管理、用真实反馈校准方向。对于任何考虑将 AI 智能体深度整合进工作流的团队，这都是一份极具实操价值的参考。
