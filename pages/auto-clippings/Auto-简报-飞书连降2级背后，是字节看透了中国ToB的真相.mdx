# 飞书连降2级背后：字节看透了中国ToB的真相——精华简报

**来源**：虎嗅网 / ToB老人家（作者：王戴明）  
**原文链接**：https://www.huxiu.com/article/4885302.html?f=rss

---

## TL;DR

飞书被拆分、产品团队并入豆包、负责人谢欣从 CEO-1 降至 CEO-3，表面上是字节“All in AI”下软件让位 AI，实则有三重逻辑：一是飞书投入产出长期未达战略预期；二是豆包企业版需要飞书的原生集成能力，但飞书角色从主平台降为能力组件；三是最根本的——字节看清了中国大企业 ToB 交付“重、慢、难盈利”的结构性困境，转而用 AI + 标准化产品切入中小企业市场，走互联网大厂更擅长的规模化分发路线。因此，拆分飞书不是放弃 ToB，而是字节 ToB 战略从“大客户定制交付”向“AI 原生、标准化、规模获客”的主动切换。

---

## 核心观点与洞察

### 1. 飞书降级的直接原因：战略投入产出严重失衡

飞书作为字节集团战略事业部已成立约 7 年，团队约 4000 人，年人力成本高达 32—40 亿元，而最新年度订阅收入仅约 30 亿元。即便未来能够盈利，其增长速度和利润水平也很难匹配字节对战略事业部的期望。

此前字节坚持投入飞书，并非因为飞书已经跑通，而是因为没有遇到更大的风口。豆包崛起后，字节在 ToB 领域看到了新的可能性，飞书被降级便成为顺理成章的选择。

### 2. 豆包企业版需要飞书，但飞书的战略地位已经改变

企业 Agent 的真正门槛不在大模型或 Harness 本身，而在于：**它能调用什么工具，以及能调用到什么程度。**

文章用金蝶举例：Workbuddy 调用金蝶 ERP，只能简单查询库存和产能；而金蝶灵基 Agent 与金蝶 ERP 原生集成，能主动根据库存和产品缺口制定订单交付策略，并推动落地。差异不在模型能力，而在是否原生集成。

同理，豆包企业版如果没有飞书，很可能沦为弱化版“WorkBuddy 企业版”；只有与飞书原生集成，才能快速做出差异化的豆包企业版。但这也意味着，飞书从“主平台”变成了“工具层/能力组件”，战略地位必然下降。

### 3. 最根本原因：字节看透了中国大企业 ToB 的“重交付陷阱”

飞书的 slogan“先进组织，先用飞书”与 SAP 的“The Best Run SAP”高度相似，本质都是：**先拿下行业头部企业，再渗透整个行业。** 这套战略在全球可行，但在中国落地异常艰难。

文章用用友与金蝶的对比说明问题：

- 用友覆盖了 2025 年《财富》中国 500 强企业中 78% 的客户，是大企业市场领导者，但亏损更严重；
- 金蝶以中小企业为主，产品标准化程度更高，订阅及软件业务毛利率高达 96.5%，盈利更稳定。

大企业项目看似客单价高，但往往一地鸡毛，原因有三：

1. **业务复杂、个性化需求多**：交付人员素质难以匹配复杂需求，需求分析容易漏项，方案被推翻、项目延期风险高；中国大企业个性化需求多且不愿妥协。
2. **甲方过于强势**：项目周期中甲方业务或组织调整带来的新增成本，往往被转嫁给乙方。
3. **付费能力有限、竞争激烈**：300 万的国产 ERP 替代项目看似金额不低，但对比交付成本往往巨亏；同类项目若由 SAP/Oracle 承接，金额大概率超过 2000 万。

因此，飞书产品、营销几乎做到极致仍无法盈利，问题不在执行，而在赛道结构本身。

### 4. 字节 ToB 逻辑切换：从“大客户交付”到“AI 标准化规模分发”

文章指出，大企业 AI 落地是一件又重又慢的活，并不适合字节这样的互联网大厂。字节真正擅长的是：**把产品做成可规模化分发的东西，用最快速度覆盖广大客群。**

豆包庞大的用户基数更容易转化为中小企业订单，可以支撑字节用互联网大厂最擅长的打法，把 ToB 做成一门规模化的生意。

所以，拆分飞书表面是不看好飞书，实质是字节看清了一件事：**在中国做 ToB，标准化、中小客群、轻交付才是更适合互联网大厂的路径。**

## 启发与影响

- **对中国 SaaS/ToB 行业**：再次验证“大企业定制化交付”是低毛利、高风险模式；标准化程度高、面向中小客群的产品更容易实现可持续盈利。企业软件公司应更重视产品化能力，而非单纯追求灯塔客户和头部订单。

- **对字节跳动**：飞书降级标志其 ToB 战略从“组织数字化平台”转向“AI 入口 + 工具生态”。豆包企业版可能走“AI Agent + 协作/业务系统原生集成”路线，以 C 端流量和用户基数撬动 B 端中小企业。

- **对 AI 企业服务竞争**：企业 Agent 的护城河不在模型本身，而在与业务系统、协作平台的深度集成和可调用工具链。拥有飞书、金蝶 ERP 等原生场景的厂商，比单纯套壳或 API 集成的玩家更具差异化优势。

- **对用友、金蝶等传统厂商**：金蝶的中小企业标准化路线在盈利上更占优；用友的大企业战略虽占据头部客户，但需警惕交付成本失控。未来 AI Agent 可能进一步放大“原生集成”的价值，传统 ERP 厂商的场景壁垒值得关注。

- **对互联网大厂 ToB 路径**：字节的调整提示，互联网大厂若沿用消费互联网的规模逻辑做 ToB，应选择标准化、可分发、轻交付的产品形态，而非陷入大客户定制交付的泥潭。
