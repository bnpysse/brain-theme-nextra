Prime Agent 是一个用于通用和长期工作的开源编码与研究代理。它围绕两个核心抽象进行设计：

- **递归语言模型（RLM）** 将上下文视为变量（*提示作为变量*），并将工具如递归子代理视作函数调用（*程序化工具/子代理调用*），在持久的REPL中运行。
- **持续性框架** 存储补充提示、记忆、技能描述以及可重用子代理规范等持久状态，Prime Agent 可以通过小范围、证据支持的更新来改进这些状态。默认情况下，这些更新仅限于会话本地。

Prime Agent 结合了一个持久性的 Python 控制环境和持久性框架状态，因此有用的工作上下文和可重用的操作模式可以超出单个聊天窗口的寿命。

- **一切都是程序化的：** 持久的 IPython 是内置的模型工具；文件操作、 shell 命令、工具使用、子代理以及上下文管理都是通过代码进行。
- **内置了子代理：** `rlm(...)` 会生成实际的孩子代理，用于并行或后台工作，并以程序化的方式返回其结果。
- **框架可以改进：** `/refine` 可以回顾当前的轨迹，并可以通过小范围、证据支持的更新来改进补充性框架状态。它从不重写不可变的基础系统提示，记录的快照支持回滚。
- **技能是可执行的：** 技能是可导入的 Python 包，内置的技能创建器可以将重复的工作流转换为项目或个人技能。
- **会话在后台运行：** 后台代理可以在终端断开连接时继续运行，并且可以稍后重新附加。
- **代理直接通信：** 运行中的代理可以直接互相发送消息并协调彼此工作，而无需通过用户进行路由。
- **长期任务持续推进：** 自动压缩、持久性目标、心跳、日程安排、自主模式以及保留的子代理保存了跨回合和终端会话的工作进度。

## 开始使用

在 macOS 或 Linux 上安装最新稳定版本：

```bash
curl -fsSL https://app.primeintellect.ai/prime-agent/install.sh | sh
```

安装程序会下载一个带有 SHA-256 校验和的版本，安装 `prime-agent` 命令，并可以为代理准备 IPython 运行时。

从你想让它工作的项目目录开始启动 Prime Agent：

```bash
cd /path/to/project
prime-agent
```

首次启动时，请运行 `/login` 以选择订阅或 API-key 提供商。Prime Agent 在当前目录中工作，可以运行命令并修改文件。请使用一次性克隆、干净的工作树或其他你可以检查和恢复的检查点。

> [!WARNING]
> Prime Agent 使用您的用户权限执行模型生成的 Python 和项目命令。其工作者进程和服务改进了生命周期隔离与恢复；它们 **不是** 安全沙盒。仅审查更改并仅使用受信任的仓库、说明、技能和扩展程序。在外部沙盒或受限环境中运行不可信代码或指令。

有用命令：

```bash
prime-agent agents                   # 浏览运行中的、空闲的以及已保存的会话
prime-agent attach <agent>           # 重新附加到一个运行中的会话
prime-agent --resume <path|id>       # 重新启动一个已保存的会话
prime-agent status                   # 检查后台服务状态
prime-agent doctor [--fix]           # 检查或修复后台服务
prime-agent update [--force]         # 更新 Prime Agent
prime-agent shutdown [--force]       # 停止每一个代理、工作者以及后台服务
```

## 适用于长期工作的构建

Prime Agent 是为长期工作而构建的，特别适用于研究中的评估。以下功能在 TUI 和独立运行时可用。

- **持续性框架：** `/refine` 可以持久化关注点和可回顾的学习，将其保存为补充提示、记忆、可重用技能描述或子代理规范，并带有记录的改进历史。它不会替代打包和审查新的可执行技能。
- **直接代理间的通信：** 运行中的代理以及保留的子代理可以相互发现、交换消息并指引工作。
- **后端支持的延续性：** 活动会话、IPython 状态、日程安排和子代理在终端断开连接时仍然运行，并且可以在稍后重新附加。
- **心跳与日程：** `/heartbeat`，`rlm_heartbeat` 和 `prime-agent schedule` 可以按周期性或特定时间点重新进入会话。
- **持久性目标：** `/goal` 保持客观及其进度在回合之间活跃，直至完成、暂停或清除。
- **有界自主模式：** `/autonomous` 在配置的回合数、令牌数和时间预算范围内继续运行，并可以执行用户定义的质量门。通过门检查只验证该门确认的内容；达到限制并不意味着任务成功。
