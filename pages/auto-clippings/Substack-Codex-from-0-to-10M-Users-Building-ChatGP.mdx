# 📰 Codex from 0 to 10M Users: Building ChatGPT Work — Akshay Nathan, OpenAI

**来源**: Latent Space
**链接**: https://www.latent.space/p/chatgpt-work

## 📝 核心主旨 (TL;DR)
OpenAI 通过内部数据发现非开发者群体对 Codex 的使用呈指数级爆发，正式推出 ChatGPT Work 将传统对话模式与代码代理模式深度融合为统一的“超级应用”。底层采用共享的 Agent Harness（代理引擎），通过差异化的 UX 策略（如隐藏 Git Diff、调整沙箱安全默认值）适配不同工作流。该战略标志着 AI 产品重心从“编程辅助”全面转向“知识工作自动化”，强调以结果为导向的意图驱动交互，并推动团队从追求开发节奏（Motion）转向关注实际产出价值（Progress），人类的核心竞争力正加速向创意构思与审美判断迁移。

## 💡 关键知识点 / 核心观点

1. **产品架构统一：共享 Harness + 差异化 UX 策略**
   - **底层一致**：ChatGPT Work 与 Codex 共用同一套 Agent Harness，支持插件、Computer Use、Artifacts、记忆系统（Chronicle）及子代理（Sub-agents），确保能力无断层。
   - **体验分流**：UI 层做“有态度”的设计取舍。Codex 模式保留 Git Repo 上下文、Diff 追踪与传统开发可见性；Work 模式则抽象底层状态机，强化文件操作与沙箱安全默认值，降低非技术用户的认知负荷。用户无需在两个独立 App 间切换，实现“一次构建，多场景分发”。

2. **从编码代理到知识工作代理的范式跃迁**
   - 知识工作长期受限于碎片化工具链（文档、表格、PPT、垂直 SaaS）。Agent 不再依赖手动点击菜单，而是直接解析自然语言目标，自动编排上下文、调用工具、组装最终产物（Artifacts）。
   - 交互形态从“静态输出”升级为“交互式站点/活页表格”。例如用可交互 Site 替代传统 PPT，或用 Agentic Spreadsheet 处理复杂动态分析，大幅提升信息传递效率与可操作性。

3. **生产力度量重构：区分“伪忙碌（Motion）”与“真进展（Progress）”**
   - LLM 大幅降低了执行门槛，但容易催生大量低效迭代（Increased Motion）。OpenAI 提出以 `Quality At-Bats`（高质量试错/有效交互轮次）替代 Commit 数、Token 消耗量或 PR 数量作为效能指标。
   - 当代码生成、排版、基础分析被 AI 接管后，人类的瓶颈将集中在 `Ideas & Taste`（创意方向与产品审美）。模型擅长组合已知要素，但难以自发生成真正具备市场洞察力与原始创新性的 Idea，人类必须重新掌握定义问题的权利。

4. **大模型配置哲学与企业级落地教训**
   - **默认优先**：OpenAI 坚持“Opinionated Defaults”原则，认为绝大多数用户应使用系统推荐的最佳实践组合。仅在面对极复杂探索任务时使用 Ultra/Multi-Agent 模式，或在需长期可验证进度的场景使用 Goal Mode。
   - **企业 AI 启示**：不存在万能模板。成功的企业级 AI 部署需深入业务毛细血管，以离散、可衡量的具体用例为切入点，并在用户当前工作流中嵌入杠杆（Meet users where they are），而非强行推行标准化平台。
