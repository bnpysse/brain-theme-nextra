# 精华简报｜千问办公发布多人工作台，重写企业软件的最后一公里

**来源**：极客公园｜作者 Cynthia｜编辑 郑玄

## TL;DR

这篇文章以 2026 年 Anthropic 扩展 Claude Cowork、千问办公上线“多人工作台”为引，重新审视企业软件的底层矛盾：SaaS 的商业模式高度依赖标准化复制，但真实企业流程几乎无法完全标准化。文章指出，办公 Agent 正在改变“谁来把公司特殊流程翻译成软件”这件事——用户不再先选 CRM、项目管理等系统，而是描述角色、任务和数据，系统即可生成带角色权限、云端数据库和管理后台的协作应用。千问办公多人工作台代表了一种从“软件复制”走向“软件生成”的转折：SaaS 不会立刻消失，但入口、交互标准和大量非标流程市场可能被办公 Agent 重写。

---

## 一、核心观点与洞察

### 1. 中国 SaaS“元年复元年”，根本卡在标准化与个性化的经济性矛盾

中国 SaaS 长期面临一个尴尬循环：需求旺盛，但规模利润转化缓慢。

- 2023 年中国 SaaS 市场规模已达 581 亿元，同比增长 23.1%；
- 但 2021 年至 2023 年，SaaS 投融资事件数减少 71%，融资金额下降 85%。

这说明企业数字化需求并未消失，只是行业高估了需求转化为软件规模化利润的速度。

真正的原因藏在 SaaS 最漂亮的商业模型里：**复用**。同一套产品卖给第一百家公司与第一万家公司，研发成本不会同步放大一百倍。但问题在于，企业越大，组织结构、审批制度、行业规则和历史系统越复杂。客户希望软件“越来越懂自己”，而软件公司只有让客户尽量使用同一套东西，才能实现规模经济。

过去二十年，企业软件一直在寻找标准化与个性化之间的“翻译接口”：配置项、开放 API、PaaS、低代码、无代码。但核心问题始终未变：

&gt; **一家公司的特殊之处，究竟由谁负责翻译成软件？**

过去，这个翻译工作主要靠实施顾问、产品经理、客户 IT 部门和开发团队完成，因此软件迭代始终跟不上业务变化。Agent 时代，这个前提发生了变化。

### 2. 个人效率不等于公司效率：阿姆达尔定律与“共享状态”

生成式 AI 最初制造了一种错觉：员工效率和公司效率似乎是一回事。

微软 2023 年 Work Trend Index 显示，员工平均 57% 的时间花在会议、邮件和聊天等沟通活动上，真正用于文档、表格和演示等内容生产的时间只占 43%。

这里可以借用 1967 年 IBM 计算机架构师 Gene Amdahl 提出的“阿姆达尔定律”：一个系统里，只要还有一部分工作无法被加速，那么无论其他部分变得多快，整体速度最终都会被那一小段未加速部分限制。

在企业组织中，这意味着：

- 销售十分钟写完客户方案，仍可能等半天才能拿到库存；
- 项目经理半小时完成排期，仍需等负责人审批；
- 市场团队一天生成二十套内容，法务审核队列反而更长。

AI 加速个体产出，反而制造了一种新的组织生产率悖论：**每个人都能制造更多输出，于是组织需要处理的审核、同步和决策反而更多**。

这也解释了为什么 CRM、ERP、项目管理软件没有因为 Excel、即时通讯或更聪明的个人工具而消失。它们的核心价值不仅是“记录”，而是让整个组织承认“这是谁的客户、现在处在哪个阶段”；让库存、订单、应收和成本对应同一组事实。

企业软件最难替代的能力是：

&gt; **共享状态——谁能看到什么，什么已经发生，事情走到哪一步，谁拥有修改权，下一步交给谁，以及事后能否还原。**

因此，个人 Agent 只能解决“我能否更快完成工作”；企业 Agent 必须解决“我们能否高效协同、共享上下文，甚至让软件生产形式围绕组织需求灵活定制”。

### 3. 多人工作台：有 SaaS 的命，没 SaaS 的“病”

SaaS 最诱人的商业模式从来不是上云，而是复制。但世界上没有一模一样流程的两家企业。

- 标准化走得太远，企业只能削足适履；
- 定制化做得太深，软件公司又会长出越来越重的实施和项目团队。

企业级办公 Agent 反转了这个逻辑：**不是让企业适应软件，而是让软件生产变得更简单，去适应不同企业流程。**

以千问办公多人工作台为例，用户不再先选择“我要做 CRM”或“我要做项目管理”，而是说清：

- 有哪些角色；
- 每个人要完成什么任务；
- 系统需要保存哪些数据。

系统据此生成一个可以在线发布的协作应用，带角色权限、云端数据库和管理后台，最多支持百人同时在线。

例如，一个百人市集活动：

- 过去需要一张表收报名，一个微信群催资料，另一张表排摊位，再单独找财务核押金；
- 现在主办方可以直接生成一套工作台：摊主提交资料、查看审核状态；主办方审核并安排摊位；财务跟进押金；
- 不同角色看到不同数据，所有人的进展保存在同一套云端数据库里。

更重要的是，办公 Agent 拥有 SaaS 平台很难天然具备的优势：**完整上下文**。传统定制项目理解一家公司业务，主要靠访谈、需求文档、流程图和实施顾问；而办公 Agent 如果已经接入员工日常使用的 IM、文档、会议、邮件和业务系统，就有机会持续知道这家公司怎么工作，不必等到立项时再从头问一遍。

### 4. 千问办公的案例与竞争身位

**旅业协同台案例**：OneX AI 社区创始人火哥有近二十年旅游行业经验。他用千问办公多人工作台搭建了一套旅业协同台，让旅行社的销售、计调和财务围绕同一笔订单工作。

旅游行业非常能暴露协作问题，因为存在“库存”：

- 销售看到还有两个位置，不代表提交订单时仍然有；
- 客户发来付款截图，不代表财务已经确认到账；
- 占位时间结束，不能保证位置可以立刻重新出售；
- 客户提出取消，退款和库存释放是两件不同的事。

火哥的第一版系统大约用半小时生成，之后只花一夜迭代，即可运行部分业务流程。在过去的 SaaS 时代，这种开发速度几乎不可想象。

**大厂动作密集**：

- 6 月，阿里率先开启内部 Agent 产品线与能力整合，将 QoderWork、悟空和 MuleRun 并入同一条产品线；
- 8 月 3 日，千问办公正式发布，称是全球首个瞄准企业级场景的 Agent；一个月更新 120 个版本，获得长安汽车、汇付天下、传化集团、科伦药业、老乡鸡在内 3000 万用户；
- 7 月 20 日，腾讯开启业务整合，QClaw 并入 WorkBuddy 体系；
- 7 月 30 日，飞书产品团队与豆包产品团队整合，飞书 GTM 团队与火山引擎合并；
- 8 月 25 日，豆包工作正式发布，并与飞书深度打通，可调用企业知识和工作上下文。

**千问办公的特殊牌**：

- 钉钉已承载超 2600 万企业组织、8 亿用户；
- 阿里云已为全球 500 万客户提供云计算服务；
- 千问办公与钉钉深度整合后，用户可以直接在钉钉里用自然语言下达任务。

于是，底层 CRM、ERP 或数据库可能仍然存在，但入口已经被办公 Agent 取代，成为新一代企业级软件的交互标准。

### 5. 长期判断：SaaS 仍是 Infra，Agent 覆盖非标长尾

文章并没有将 Agent 与 SaaS 简单对立，而是给出更冷静的判断：

- 财务总账不会因为一句 Prompt 就变得不需要审计；
- 银行、制造、医疗等关键系统背后的行业规则、权限、安全和合规，不是模型几轮对话就能重新学习；
- **SaaS 依然是最重要的 Infra**。

但建立在已有基础设施之上，办公级 Agent 依托协作能力与完整上下文，打开了一个更大的蓝海：

&gt; 那些不广泛存在于每家企业标准流程中，但足够重要的非标流程与项目。

这些可能是：

- 一场只办三个月的活动；
- 一个几十人参与的供应商项目；
- 一个总部临时发起的新店筹备流程；
- 一家只有十几个人，却有销售、财务、供应商和客户共同参与的公司。

更长远来看，这是**软件生产变革的开始**。

## 二、对行业的启发与影响

### 对 SaaS / 企业软件厂商

- 不能继续在“标准化 vs 定制化”之间做线性取舍。Agent 层可能成为新的交付和交互入口，SaaS 厂商需要把产品能力下沉为可被 Agent 调用的基础设施，而不是继续教育客户适应菜单和字段。
- “共享状态”仍然是企业软件的核心价值。谁能用 Agent 重建可信、可审计、可追溯的共享状态，谁就掌握了下一代企业软件的制高点。
- 入口正在从独立系统转向 IM、办公平台和自然语言交互。无法接入完整上下文的单点工具，可能被加速边缘化。

### 对企业客户

- 软件采购与实施逻辑可能出现变化：从“选一套系统让组织适配”，转向“描述业务规则生成协作台”。
- 实施周期可能从月、年降至小时、天，但企业需要重新设计数据归属、权限边界、合规审计和关键系统治理，不能把共享状态完全交给黑箱模型。
- 企业数字化部门的价值，将从“需求翻译与项目管理”转向“业务规则设计、Agent 治理与异常处理”。

### 对组织管理

- 提效工具已经足够多，下一阶段竞争在“组织速度”。管理者需要优化审核、同步和决策瓶颈，而不只是继续堆个人生产力。
- 阿姆达尔定律对企业管理的启发：局部加速如果不能改善协作瓶颈，组织整体效率仍然无法提升。

### 对投资与产业判断

- 资本市场对 Agent 替代 SaaS 的反应已经先行：美股软件股单日下跌 6%，软件、金融服务和资产管理相关股票合计蒸发约 2850 亿美元；Wind 香港 SaaS 指数下跌 6.39%，板块总市值缩水近 150 亿港元。
- 真正分水岭在于：谁掌握企业完整上下文，谁能把 Agent 与底层业务系统打通，谁能建立新的“共享状态”标准。
- 拥有 IM、云、账号、组织架构体系的平台公司，在企业级 Agent 竞争中具备结构性优势。

### 对创业生态

- 非标长尾流程可能成为新市场，但创业公司需要依附平台流量、数据、权限和分发体系。
- 护城河将来自行业 know-how、可沉淀的 Agent 模板，以及围绕特定业务场景的规则设计能力，而非单纯的软件功能复制。
- 下一代软件竞争的关键，不再只是“你做了多少个功能”，而是“你能多快生成一个贴合具体组织、具体业务的协作系统”。
