### 精华简报：Agent 引擎优化（AEO）——AI 时代的产品设计新范式  
**来源**：极客公园《判断用不用你的软件，Agent 只需 500 个 Token》  
**核心观点**：AI Agent 正在成为软件的“沉默用户”，其选择工具的方式与人类截然不同。产品若未针对 Agent 优化（AEO），可能被无声淘汰，而企业甚至无法感知这一过程。

---

#### **一、Agent 如何“审判”你的产品？**  
1. **效率至上**：  
   - Agent 读取文档仅需 **400 毫秒**，通过单次 HTTP 请求完成决策，而非人类的多步骤浏览。  
   - **前 500 Token 决定生死**：必须清晰回答“是什么、能干什么、怎么开始”，否则 Agent 会放弃或编造答案。  
2. **Token 预算限制**：  
   - 文档过长（如思科 API 指南达 19 万 Token）会导致 Agent 截断、跳过或回退到错误记忆。  
   - 建议：快速入门指南 ≤15K Token，API 参考页 ≤25K Token，概念指南 ≤20K Token。  
3. **无视 UI 设计**：  
   - Agent 只解析纯文本，HTML 中的导航栏、交互元素等均被视为噪音，且消耗额外 Token。

---

#### **二、AEO 六层优化框架**  
1. **修复 robots.txt**（优先级最高）：  
   - 检查是否误封 AI 爬虫（如 OpenAI、Anthropic），否则 Agent 会直接跳过且不留痕迹。  
2. **发布 llms.txt**（Agent 版 Sitemap）：  
   - Markdown 格式，列明文档结构、每页内容摘要及 Token 数，帮助 Agent 精准定位。  
3. **编写 skill.md**（产品自荐信）：  
   - 简明列出核心能力、输入要求、限制条件，让 Agent 快速判断适用性。  
4. **提供 Markdown 版本文档**：  
   - 纯文本比 HTML 节省 Token，避免因 JavaScript 渲染导致内容不可读。  
5. **暴露 Token 数元数据**：  
   - 在 HTTP 头或 meta tag 中标注 Token 数，供 Agent 提前决策。  
6. **添加 “Copy for AI” 按钮**：  
   - 一键复制清洁版 Markdown 内容，提升 Agent 上下文质量（如 Cloudflare 已实现）。  

---

#### **三、AEO 的深层价值**  
- **双赢设计**：AEO 原则（如内容前置、结构清晰）同样提升人类用户体验，但 Agent 的容错率为零。  
- **沉默的真相**：传统分析工具将 Agent 流量标记为“低质量访客”，实际它们正在重塑工具生态。  
- **未来趋势**：  
  - Agent 选择工具时“冷酷客观”，仅基于实用性，品牌营销无效。  
  - Lighthouse 等工具已开始支持 llms.txt 检查，AEO 或成行业标配。  

---

**行动建议**：企业需优先审计 robots.txt 和文档 Token 效率，逐步实施 AEO 六层框架，以抢占 Agent 生态的“默认选择”优势。
