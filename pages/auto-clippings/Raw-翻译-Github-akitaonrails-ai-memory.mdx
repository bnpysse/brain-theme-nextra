## 为什么选择ai-memory

您的编程助手已有记忆功能。Claude Code会自行记录笔记，Cursor能记住部分内容，每个平台都在强化此功能。但它们都存在相同局限：笔记仅存于单台设备、属于单一代理，切换工具或队友时立即失效。

ai-memory正是突破这些局限的解决方案。

- **跨代理记忆跟随**：二十多种适配器（Claude Code、Codex、Cursor、Gemini CLI、OpenCode、Grok、Devin、Kimi、Kiro等）共享同一记忆库。在任务中途关闭Claude Code后，于同目录启动Codex时，新代理能获取完整交接：包括中断位置、失败尝试和待解决问题。这里的交接是严格协议而非约定——具备类型定义、所有权声明和一次性认领机制。

- **跨设备同步**：记忆存储于您控制的服务器（笔记本/家庭服务器等），使得桌面端暂停的项目可在笔记本无缝续接。知识脉络与开放问题始终保持一致。

- **团队协作支持**：全员指向同一服务器时，任一成员的会话学习成果可供所有代理检索。知识按项目共享，个人交接记录保持私密。内置多用户认证、贡献追踪和审计日志——这些都不是付费功能。

- **纯Markdown记忆库**：原始数据存储为git托管的普通`.md`文件wiki，支持`grep`搜索、Obsidian查看、手工编辑或`rsync`同步。数据库仅是可根据文件重建的索引，无需维护向量存储，没有二进制劫持风险。

- **无感工作捕获**：通过生命周期钩子自动记录真实工作轨迹（提示词、工具调用、会话边界），经类型化隐私过滤后存储，最终整合为可读页面。无需"记住这个"操作。默认路径**零LLM调用**：捕获、搜索和交接全程无需API密钥。

- **透明系统设计**：单一可执行文件。清除命令明确说明删除范围。实测写入上限（约700次/秒）取代猜测值。所有变更皆有审计日志。如同基础设施应有的模样——稳定可靠。

## 工作原理

```
捕获 ──▶ 整合 ──▶ 检索 ──▶ 交接
 钩子      会话结束     搜索      下个代理
 静默观察   生成wiki摘要    + 简报注入   任意适配器
```

工作时，代理通过生命周期钩子发送经净化的观察记录。会话结束时，这些记录将转译为连贯的markdown页面（可选LLM润色，但原始版本已可用）。后续会话（任意代理/设备）会获取限定简报，并能搜索全部内容：全文、实体、链接及（可选的）向量——统一排序呈现。跨代理交接通过显式协议传递上下文。

完整设计（包括保障多用户多会话安全的约束条件）详见[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。
