【文章标题】：2026年大语言模型发展现状（截至当前）

【文章正文】：
上周五我在圣何塞举行的
WeAreDevelopers世界大会北美站
做了闭幕主题演讲。我将过去一年的关键趋势串联起来，按时间顺序梳理了2026年发生的所有重大事件。演讲视频
已上传至YouTube
；这里附上我带有批注的演讲幻灯片和笔记。

#
我将快速带大家回顾2026年迄今为止的所有重要进展。毕竟这一年还没结束呢！

#
对我而言，2026年其实早在2025年11月就开始了。

#
11月发布了两款重要模型：Claude Opus 4.5和GPT-5.1。
和往常的新模型发布一样，它们都是在前代基础上的渐进式改进。
但偶尔当模型进化到某个程度时，会突破某个看不见的临界点——让原本行不通的功能突然变得可用。
这次突破的是它们的编程助手功能。Claude Code早在2025年2月就问世了，Codex则稍晚些。
这两款新模型搭配各自的编程助手框架后，从"经常出错"进化到了"日常使用足够可靠"的水平。

#
这两年我有个独特的模型测试方法：让AI"生成一张鹈鹕骑自行车的SVG图片"。这可能是全世界最愚蠢的基准测试——能获取的信息量很有限。
但对模型来说仍具挑战性，因为绘制鹈鹕很难，画自行车也不容易，更何况鹈鹕本来就不会骑车。
这是11月时的最佳表现。Claude还是画不好自行车！GPT-5.1的车架也很糟糕。

#
同样在11月，一个名为"Warelay"的冷门GitHub仓库出现了首次提交。我们稍后会再提到这个仓库。

#
接着是12月的假期季，独立开发者们开始休假，许多人开始捣鼓这些新的编程助手组合...我们逐渐意识到它们能实现以往做不到的事情。
到了一月份，很多人都摩拳擦掌准备大干一场。

#
每年我都会制定新年计划，而我的计划多年来始终如一：保持专注。少接新项目。努力完成现有项目。

#
今年我决定换个思路——既然老方法从没奏效过。
现在有了编程助手，正好测试它们的能耐。我要随心所欲地开展新项目！
（年底你们可以问我这个决定是否明智。目前我手头同时进行的项目
多到爆炸）

"更大胆些"可说是今年的主题，因为只有不断挑战技术边界，才能发现它的极限所在。

#
我还参加了
Oxide and friends播客
与Bryan Cantrill和Adam Leventhal共同预测未来一年（以及三年、六年）的发展。
现在看来，我对大语言模型的预测实在太过保守。
我说过"LLM能写出优秀代码将成为不争事实"——现在已然实现。
我预言我们会最终解决沙盒安全问题。本次大会277场演讲中约有40场
涉及沙盒或智能体安全议题，说明业界至少投入了大量精力！
我曾预测"编程助手安全将出现挑战者号级别的灾难"。今年确实出现大量相关讨论，不过我预想的具体场景（编程助手被劫持造成实际经济损失）尚未发生。
我们还开了个
玩笑式预测
说教皇会就LLM的经济影响发表意见。

#
我还预言新西兰鸮鹦鹉今年会有超常的繁殖季。
这种鸟类栖息在新西兰。它们是夜间活动、不会飞的鹦鹉。看起来圆滚滚的很呆萌，我觉得特别可爱，今年初全球仅存236只。
鸮鹦鹉只在罗汉松果实丰产时才会繁殖，而这种情况已四年未现...但今年罗汉松果实长势极好。
Kimberley Collins拍摄的照片

#
在那期播客中，我们还创造了个术语（功劳全归Adam）来描述"AI引发的倦怠感——软件工程师因AI无所不能而产生迷茫"。
我们称之为
深蓝忧郁
。
这成为贯穿全年的主题，多位大会演讲者都提及相关现象。
作为软件工程师，我职业生涯中从未经历过如此剧烈快速的变革。
今年我花了很多时间来消化这个现实，并思考它对职业发展的意义。
