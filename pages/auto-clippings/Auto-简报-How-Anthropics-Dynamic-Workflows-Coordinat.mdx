# 精华简报

## 核心主题

Anthropic 在 AI Engineer NYC 2026 大会上发布了 **动态工作流（Dynamic Workflows / Flows）**——一种全新的多智能体编排方式，允许 Claude 自主决定如何组织、协调和调度子智能体，面向大规模、高复杂度的任务场景。

## 关键要点

### 1. 从“人肉协调”到“Claude 自主编排”

- 传统模式下，开发者需要手动配置协调器（coordinator）和子智能体名单（roster），并逐一审批 PR、管理任务流转，容易成为瓶颈。

- **Flows 的核心创新**：Claude 自己编写编排程序，自主决定多智能体拓扑结构，启动子智能体、收集结果、管理信息流，开发者无需干预中间连接。

- 用户仍可在配置中传入预置的专家子智能体，实现“自主 + 可控”的混合模式。

### 2. 工作方式

- 主智能体（lead agent）先制定任务计划，然后生成一个“编排程序”，由该程序负责调度多个子智能体，分阶段完成**可验证的独立工作单元**。

- 演示案例（股票观察列表扫描器）展示了基本模式：扫描阶段将不同股票分发给隔离上下文的子智能体，评审阶段汇总结果并生成报告。

### 3. 预算与效率问题（Q&A 亮点）

- **智能体数量控制**：Claude 默认保守，主要通过 evals 和较低默认并行度来避免“任务简单却触发数百个子智能体”的情况；高并行需要显式鼓励。

- **Token 预算**：模型运行时不感知自身预算，但开发者可设置会话预算。有趣的是，Anthropic 认为让模型知道预算可能让智能体“有点焦虑”。

- **重复流程降本增效**：推荐使用 **“做梦”（Dreaming）** 功能——一种研究预览特性，能读取现有记忆库和过往会话记录，合并重复项、替换过时/矛盾条目、提炼新洞察，从而优化记忆存储，使后续流程更高效。

- **流程自我改进**：目前尚未内置“自动识别模型缺陷并调整下次运行”的能力，但可通过 **爬山算法（hill-climbing）** 和 **dreaming** 组合实现循环优化。

## 背景与定位

- Flows 源于 Claude Code 中“为每个任务提供 harness”的概念，但可运行时间远超单个智能体或固定名单。

- 类比操作系统发展史（Unix → Linux 的分层维护者机制），Anthropic 认为智能体需要同样级别的组织能力，才能完成宏大的工程项目。

- 该功能已上线 **Claude Console**（面向通过 API 使用 Claude 的开发者），是 Claude Managed Agents 体系的一部分。

## 分析师评论

动态工作流标志着多智能体编排从“开发者定义结构”向“模型自主设计结构”的关键转变。其价值在于降低大规模任务中的人类协调负担，但代价是可控性和可预测性下降。Anthropic 通过默认保守的并行度、会话预算限制、以及 dreaming 记忆优化机制，试图在自主性与成本/风险之间取得平衡。对于追求极致效率的团队，这是一个值得关注的方向；但生产环境中仍需结合 evals 和人工监督来确保质量。
