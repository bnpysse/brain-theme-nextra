【文章标题】：AI 时代的 Surface Pro 7 改造指南：看板、轻量工作站与 Linux 笔记本

【文章正文】：
手头这台闲置的 Surface Pro 7 在桌角放了挺长一段时间。当年买它看重的是二合一的便携形态，但放在 Windows 11 下只要长时间亮屏就一定会过热、偶尔跳屏，基本处于不可用的状态。
直到前阵子在网上看到有人把墨水屏做成桌边状态看板，我才想起来这块屏幕其实很合适：自带无极调节支架、一块 3:2 比例的高分屏、能独立运行完整系统，有需要时随时还能吸上键盘。
把这台机器刷成 Linux 之后，它立在桌边成了常驻的 AI 用量看板和轻量工作站，闲置硬件刚好彻底利用起来。
这次改造整个过程都是让 AI 帮我看着弄的，这里记录一下流程里比较顺手的工作流、几个关键排错点，以及它最终呈现的几种实用形态。
第一步：直接把硬件和需求丢给 AI
最终使用的 Ubuntu 24.04 LTS、用 Rufus 写盘、整盘抹掉 Windows 以及全盘加密，都是在跟 AI 讨论的过程中定下来的。
动手前，我直接在对话框里说明了硬件底细和想法：
    我手头有台闲置的 Surface Pro 7（i5 / 8G / 256G），目前是 Win11。我想把它改成桌边常亮的 Linux 用量看板，偶尔 SSH 上去跑点东西。你帮我看看适合刷什么系统？怎么做最稳妥？
在这个过程中，AI 根据当时的官方文档，反过来引导我理清了几个具体的选择：
- 系统与引导：因为不打算保留 Windows，直接选择整盘格式化，省去复杂的双系统分区麻烦。
- 全盘加密：考虑到 Surface 毕竟是个便携的二合一设备，偶尔可能带出门用，所以我开启了 Ubuntu 的全盘加密（LUKS）。
- 启动盘与驱动：AI 推荐用 Rufus 写入 Ubuntu 24.04 镜像，并提醒 Surface 的触控和手写笔需要后续安装专用的 linux-surface 内核。
技术路线确定好后，就可以直接开始写盘。
第二步：重启进 BIOS 前，让 AI 生成一份手机交接 Prompt
在 Windows 里，AI 可以随时帮我们查镜像、核对哈希值。但写好 U 盘准备重启时，眼前这台电脑上的 AI 就要随着关机一起下线了。
到了这一步，最顺手的做法是直接让电脑上的 AI 生成一段简短的跨设备交接 Prompt：
    我现在要关机重启进入 UEFI 装系统了。请给我生成一段交代当前进度、配置目标和注意事项的 Prompt，我直接发给手机上的 AI，让它接管接下来的安装向导。
把生成好的 Prompt 复制粘贴到手机的 AI 对话框里，手机端的 AI 就能立刻接上进度。
接下来在物理安装过程中：
- 物理按键引导：Surface 从 U 盘冷启动需要按住音量减小键再按电源键，直接看手机 AI 的提示，不用到处搜文档。
- 菜单与选项确认：在 UEFI 设置启动顺序、在 Ubuntu 安装器里选择目标磁盘和加密选项时，拿不准的地方拍张照发给手机 AI，让它指出具体选哪一项。
- 状态确认：写盘进度条看似停滞时，拍图发过去，AI 也能根据当前解包的日志判断是否在正常写入。
第三步：进入系统，让终端 Agent 接手驱动配置
顺利走完安装向导后，机器重启进入了 Ubuntu 桌面。
刚装好的原生 Linux 默认是不支持 Surface 触控的，屏幕点上去毫无反应。所以在完成初始配置和驱动安装之前，一定要吸上 Type Cover 键盘（或者接一套外接键鼠）。接上键盘打开终端，装好日常用的 Agent 之后，驱动配置就可以直接交给它了。
要让 Surface 的触控、手写笔和电源管理正常工作，核心是换上社区维护的 linux-surface 内核。我在终端里直接让 Agent 查一下这台机器上的 linux-surface 内核装好了没有，没装好就帮我装上。Agent 检查了系统的包管理和正在运行的内核，发现软件源和签名密钥已经有了，但核心的内核包并没有装上，系统依然在跑 Ubuntu 默认的通用内核。
在我的确认下，Agent 安装了 linux-image-surface（当时版本是 6.19.8-surface-3）及配套的触控组件，并准备好了 Secure Boot 所需的 MOK 签名。
现场排错：装好包与实际启用
对于 Secure Boot 开启的设备来说，命令跑完往往只是第一步。
第一次重启后我发现触屏依然没动静。让 Agent 检查后发现系统依然落回了默认内核，原因有两个：
- 机器重启时弹出的蓝色 MokManager 界面里，我漏按了一步确认导致密钥没登记上；
- GRUB 启动项因为版本号排序，依然优先引导了原版的通用内核。
我跟 Agent 说「刚刚没操作好，能不能再来一次」。Agent 重新帮我导入了 MOK 密钥、调整了 GRUB 的默认引导顺序，并把蓝色界面里的操作顺序交代清楚。
第二次重启并在蓝屏引导界面完成确认后，Agent 再次核对了 uname -r、MOK 状态和输入设备列表，确认系统已经真正跑在 6.19.8-surface-3 内核上，屏幕触控和手写笔也终于全部正常了。
全盘加密的小插曲：不插键盘怎么开机？
驱动配好后，我遇到了一个麻烦：装系统时顺手开了全盘加密（LUKS），但平板立在桌上当看板时平时是不插键盘的。LUKS 磁盘解密发生在系统启动的最早期，这时候触控驱动根本还没加载。每次开机都卡在密码框，必须特地找来键盘插上去敲密码，很不顺手。
我问 Agent 有没有办法不插键盘开机。Agent 提供了基于 TPM2 芯片做自动解锁的方案。在它的指导下，我装好了 Clevis 等工具并完成了 TPM 绑定（基于 PCR 7 绑定 Secure Boot 状态），原来的密码依然保留备用。改完之后，开机直接自动解密进入系统，立在桌上用起来就省事多了。
从「吃灰闲置」到三种实用形态
折腾完内核和驱动之后，这台原本在 Windows 11 下发热、跳屏、几乎沦为电子垃圾的 Surface Pro 7，在 Linux 下彻底展现出了它的多面性。
在我的日常工作流里，它主要有三种实用形态：
1. 桌边常驻看板与摸鱼屏
这是它平时最主要的状态。立在显示器旁边，全屏常驻跑着我自己开发的开源项目 AI Usage Dashboard（本地优先应用，从本机直接请求各服务商 API 接口，无云端中转）。相比墨水屏，这块 3:2 的高分屏能展示的信息更多，刷新没有残影，DIY 空间也大。我开启了低功耗模式，关掉动画并将刷新间隔拉长，一眼就能看清 Claude Code、Codex、Grok 的用量重置时间以及 DeepSeek API 余额。
平时在主力机上做 Vibe Coding 的时候，经常需要等待 AI 生成代码、跑测试或执行长任务。在这段等待的空档，抬手在 Surface 触屏上点几下，看个 B 站直播或视频摸摸鱼，体验很顺畅。
