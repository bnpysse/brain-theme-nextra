# 📰 The Automated Job Search Step 1

**来源**: The Wondrous Mind of Dereck Bearsong
**链接**: https://dereckbearsong.substack.com/p/the-automated-job-search-step-1

## 📝 核心主旨 (TL;DR)
作者分享了一套低成本、半自动化的求职筛选工作流：通过浏览器插件绕过招聘网站反爬限制获取职位数据，并利用本地大语言模型（Ollama）构建了两个 AI Agent（分别针对“职位标题”和“职位描述”进行量化打分），从而在海量招聘信息中高效、精准地筛选出高匹配度的目标岗位，将精力聚焦于最终的申请与人际连接。

## 💡 关键知识点 / 核心观点
1. **低成本/半自动化数据获取策略 (Workaround)**
   面对招聘平台（如 Indeed/LinkedIn）严格的反爬机制以及高昂的付费抓取 API 成本，作者采用折中方案：使用浏览器插件（如 Easy Scraper）抓取过去 24 小时的基础职位列表（标题、公司、薪资等），并手动补充职位描述（JD）。这种“半自动”方式在零成本前提下保证了数据获取的可行性，未来计划引入 Playwright 或 Selenium 实现全自动化。
2. **分层漏斗式 AI 筛选工作流架构**
   将筛选过程拆分为两个主工作流和一个去重子工作流：
   * **初筛（标题匹配）**：利用 JS 脚本去重后，让 AI 对比“职位标题”与“个人技能/过往经历”打分，筛选 >80 分的岗位。
   * **人工介入**：对初筛结果进行人工复核，并手动填入 JD。
   * **精筛（JD 匹配）**：让 AI 对比“JD”与“完整简历”进行深度打分，筛选 >90 分的岗位。
   这种分层设计有效降低了 AI 处理长文本（JD）的计算成本，同时通过人工卡点提高了最终匹配的准确率。
3. **精细化的 Prompt 工程与量化评分 Rubric**
   为“职位标题评分 Agent”设计了严格的百分制评分量表，涵盖核心标题相似度(30分)、功能技能重叠(30分)、行业相关性(20分)等维度。更关键的是引入了**明确的奖惩机制**：对不想要的岗位（如 Manager, SRE, Security Engineer）直接扣除 20 分，对偏好的岗位（如 Support Engineer）增加 30 分，使 AI 的打分逻辑高度贴合求职者的实际职业偏好。
4. **本地大模型（Local LLM）的输出稳定性控制**
   针对本地模型（如 Qwen 3）容易出现的 JSON 格式崩溃和复杂指令（如加减分规则）遵循不佳的问题，作者在 Prompt 中加入了强制校验指令（如“Review the output results twice”、“Verify the output results match the structure”），并配合严格的 JSON Schema 约束。同时，通过微调生成参数（Temperature 0.4, Top K 5.0, Top P 0.6）来平衡输出的稳定性与准确性。

## 🏷️ 提及的重要概念/公司/模型
* **工具与框架**: Easy Scraper (浏览器抓取插件), Playwright, Selenium (自动化测试/爬虫框架), Ollama (本地大模型运行框架), SearXNG (开源搜索引擎，用于 Agent 联网搜索公司背景)。
* **AI 模型**: Qwen 3 (通义千问，作者指出其在复杂加减分规则上表现不佳), Mistral (作者计划尝试的替代模型), Gemini, ChatGPT。
* **平台与公司**: Indeed, LinkedIn, Anthropic (示例数据中提及), GitHub。
* **专业词汇**: Web Scraping API, Job Listing API, JSON Schema, Prompt Rubric (评分量表), AI Agent, Deduplicate (去重), Temperature/Top K/Top P (模型生成参数)。
