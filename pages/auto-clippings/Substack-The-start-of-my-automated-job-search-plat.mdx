# 📰 The start of my automated job search platform

**来源**: The Wondrous Mind of Dereck Bearsong
**链接**: https://dereckbearsong.substack.com/p/the-start-of-my-automated-job-search

## 📝 核心主旨 (TL;DR)
作者在被Atlassian裁员后，为应对传统求职流程中“双边失效”（求职者深陷低效流程与虚假职位，招聘者被AI同质化简历淹没）的痛点，决定利用AI和自动化工具构建一个高度定制化的自动化求职平台。该项目将求职拆解为11个可工程化的核心节点，通过自动化Pipeline实现精准匹配，同时严格界定AI的使用边界，拒绝盲目海投与AI代写，以在招聘市场中建立真实的差异化竞争优势。

## 💡 关键知识点 / 核心观点

1. **传统求职系统的失效与重构逻辑**
   当前招聘市场陷入僵局：求职者面临冗长申请、虚假职位和零回复；招聘者则被海量未读、同质化甚至AI生成的简历淹没。传统的“海投”模式已彻底失效，破局的核心在于从“流量思维”转向“精准匹配”，通过自动化手段提高求职的信噪比，让“对的人”主动发现你。

2. **自动化求职 Pipeline 的 11 步核心架构**
   作者将求职过程拆解为可自动化的工程节点，形成完整的业务流：
   - **数据获取与清洗**：寻找相关职位列表并验证职位真实性。
   - **特征工程与分析**：识别个人核心优势、深度研究公司背景及招聘团队的痛点。
   - **内容生成与定制**：针对性定制简历与求职信，并构建解决招聘团队痛点的专属提案。
   - **网络拓扑构建**：精准识别并连接公司内部的招聘经理与关键人脉。
   - **面试预测与知识库**：基于JD和简历生成预测问题库，并匹配相应的STAR故事库。

3. **AI 工具使用的边界控制（Do's & Don'ts）**
   在引入AI时，强调“人机协同”而非“完全托管”。
   - **Do's**：充分利用 n8n、Python、JS 等全栈工具链实现流程自动化。
   - **Don'ts**：严禁让 AI 直接代写简历、回复或面试答案（招聘方已对过度AI化的内容产生疲劳与反感），AI 应仅作为“思路启发器”；严禁“海投（Spray and Pray）”，每次投递必须经过人工审查，确保意图明确且高度匹配。

4. **底层数据获取的工程挑战与架构权衡 (Trade-offs)**
   在构建职位数据源时面临典型的工程取舍：
   - **API 调用**：受限于权限，多数招聘板无公开API或需昂贵的企业版。
   - **Web Scraping (本地爬虫)**：易违反平台 TOS (服务条款) 导致 IP 封禁。
   - **第三方抓取服务**：存在复杂的 URL 适配与配置成本。
   - **Newsletter/RSS 聚合**：部署最轻量，但存在数据召回率（Recall）不足的问题，容易漏掉未收录的职位。

## 🏷️ 提及的重要概念/公司/模型

- **公司/平台**: Atlassian
- **工具/技术栈**: n8n (自动化工作流引擎), Python, JavaScript, API (应用程序接口), Web Scraping (网页抓取)
- **行业概念/专业词汇**: 
  - Automated job search platform (自动化求职平台)
  - Spray and pray (海投/盲目投递策略)
  - TOS (Terms of Service, 服务条款)
  - Newsletters (招聘通讯/简报聚合)
