### 🔍 TL;DR（核心摘要）
作者正为无向完全图（节点代表目的地，边代表距离）寻找高效的 Rust 数据表示方案，在权衡传统三角矩阵后发现必须依赖辅助数组完成业务标识与矩阵坐标的转译，进而探索是否存在原生支持“顺序无关键值对查询”的映射结构，并担忧自行实现可能引发索引管理复杂化、性能损耗及隐藏边界 Bug。

### 📌 核心观点与技术细节
- **图拓扑特征**：无向完全图（Undirected Complete Graph），边权具对称性，查询粒度为任意两节点间的距离，要求高并发/低延迟读取。
- **存储结构取舍**：初期采用上/下三角矩阵可节约约 50% 空间，但暴露出强依赖外部索引映射表的问题；转向映射方案旨在取消中间转译层，实现 `destination_A ↔ destination_B → distance` 的直接路由。
- **“三角地图”技术实质**：本质是键规范化（Key Normalization）需求，即通过内部自动执行 `min/max` 排序或哈希折叠，将无序对 `(A,B)` 与 `(B,A)` 收敛至同一存储槽位，消除用户态的手动归一化逻辑。
- **Rust 生态现状映射**：标准库 `HashMap`/`IndexMap` 默认按精确键匹配，缺乏内置的“组合键忽略顺序”语义；主流图算法库（如 `petgraph`）侧重遍历与路径计算，未提供轻量级距离查表的垂直封装。
- **工程风险预警**：作者对“自研数据结构”持审慎态度，反映出 Rust 开发者对零成本抽象、内存安全及生命周期管理的严格把控，避免陷入过度优化或线程不安全陷阱。

### 【核心痛点】
**如何在 Rust 中以最低的开发摩擦与运行时开销，安全、优雅地实现无向图的“无序顶点对距离查找”，彻底剥离手动维护顶点索引与键顺序归一化的样板代码，同时在类型安全、缓存友好性与生态兼容性之间取得平衡。**
