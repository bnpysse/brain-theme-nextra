背景交代完毕，现在开始探索新特性。
这是本次版本的重头戏。PostgreSQL 19实现了SQL:2023标准的属性图部分——SQL/PGQ。您可以在现有表上声明属性图，然后通过模式匹配进行查询，无需自行编写连接语句。
两个普通表，在其上构建一个图：
CREATE PROPERTY GRAPH social
    VERTEX TABLES (
        person KEY (id) LABEL person PROPERTIES (id, name)
    )
    EDGE TABLES (
        follows KEY (follower, followee)
            SOURCE KEY (follower) REFERENCES person (id)
            DESTINATION KEY (followee) REFERENCES person (id)
            LABEL follows
    );
无需复制数据：social是一个视图类对象，表示"person行是顶点，follows行是边"。现在您可以用GRAPH_TABLE进行模式匹配，其中-[...]-&gt;表示有向边：
SELECT * FROM GRAPH_TABLE (social
    MATCH (a IS person)-[IS follows]-&gt;(b IS person)
    COLUMNS (a.name AS follower, b.name AS followee)
) ORDER BY follower, followee;

    COLUMNS (a.name AS start, c.name AS friend_of_friend)

计划从图数据库迁移前需注意一个限制：初始版本不支持可变长度路径。虽然-[IS follows]-&gt;&#123;1,3&#125;这类量词能通过解析，但会报错"不支持元素模式量词"，因此模式必须明确写出每一跳。
UPDATE和DELETE的新FOR PORTION OF子句可操作范围列的数据片段。您只需指定子时间段，PostgreSQL就会自动拆分行记录，无需重写整个有效期。
表初始只有一行：2026年全年有效的价格。现在仅修改7月份的价格，然后再次查询：
SELECT * FROM price ORDER BY valid_at;
UPDATE price
    FOR PORTION OF valid_at FROM '2026-07-01' TO '2026-08-01'
    SET amount = 7.99;
SELECT * FROM price ORDER BY valid_at;
