# 精华简报：当智能体开始替人花钱，如何证明「它是谁」？

&gt; 来源：极客公园  
&gt; 链接：[http://www.geekpark.net/news/370440](http://www.geekpark.net/news/370440)

## TL;DR

当智能体从“对话展示能力”走向“替人完成真实商业交易”，最大的障碍不是模型能力，而是信任基础设施。蚂蚁集团在外滩大会发布的 **APASS**，基于 **KYA（认知你的智能体）** 理念，通过“身份信任链”和“意图信任链”，尝试系统解决四个问题：**这个 Agent 到底是谁、它被允许做什么、执行中会不会跑偏、出了差错谁来负责**。其核心逻辑是：只有把授权边界结构化、让运行中的代码有可靠身份锚点、给自主执行链路加实时风控与事后存证，用户才敢把钱包真正交给 AI。

---

## 核心观点与技术/商业洞察

### 1. 智能体商业的“ChatGPT 时刻”，卡在信任而不是技术

蚂蚁集团 CEO 韩歆毅提出，智能体商业的“ChatGPT 时刻”正在到来，标志是从对话能力走向真实商业交易闭环。调用 API 扣费、定期支付等技术早已成熟，但真正阻止用户放权的，是 Agent 与传统自动化脚本的本质不同：

- 传统自动化扣款跑在**封闭受控系统**中，规则固定；
- Agent 需要在**开放网络**里自主探索、解析未经清洗的网页、调用第三方插件；
- 过去一次性给出的静态免密授权，在长链条自主决策中可能变成“无法兜底的空白支票”。

因此，问题不只在于“能不能付款”，而在于**在开放、不确定、跨主体环境里，能否持续核验身份、意图与行为**。

### 2. 身份真空：换了台电脑，商家还认识你吗？

过去商业世界的身份确认依赖物理实体：App 加密签名、指纹人脸、法定实名。但 Agent 时代，这些锚点失效了。

典型场景是：开发者在家里电脑上配置好购物 Agent，随后把代码镜像、运行配置与记忆上下文迁移到云端容器。设备、IP、模型、插件全部变化，静态 API Key 无法判断眼前程序是否还是原来那个获批的助手，还是被克隆篡改后的仿冒品。

APASS 为此提供三个维度的身份核验：

1. **软件本身特征**：校验 Agent 的代码指纹、软件版本、挂载 Skill 清单，确认核心组件未被替换；
2. **运行时环境状态**：通过硬件级可信根与运行环境检测，判断宿主设备是否可信、环境是否存在漏洞或异常进程挂钩；
3. **真实责任主体**：将 Agent 标识与既有 KYC（个人认证）或 KYB（企业认证）关联，确保一旦发生纠纷，能找到现实中的自然人或法人。

这三点合并后，一段到处流转的代码才不再是一个“黑盒”。

### 3. 授权悖论：免密体验与失控风险如何兼得

用户让 Agent 做一份行业 PPT，它可能自主拆解出多笔跨商家的微额交易：查文献、买模板、下载图标。如果每一笔都要弹窗做人脸核验，Agent 的代办价值就没了；但如果完全免密，用户则要承担意外支出。

APASS 的做法是：**把信任结构化为具体的授权策略（Scope）**。

- 用户不必逐笔确认，而是在任务开始前圈定边界：单笔/累计预算、消费类目、商户白名单、有效时间窗口；
- L2 授权对应已明确授权的部分任务，例如在约定额度内买杯咖啡，可直接执行；
- L3 则面向一项完整目标任务，例如在预设预算与类目内，自主协调查论文、买模板、买图标等多个子任务。

这本质上是把“可控放权”的产品化：默认安全，但不牺牲智能体的连续性执行体验。

### 4. 意图漂移：如何防止“买苏打水”变成“买黄金”

授权之后的风险在于，订单到达底层收银台时，接口格式、参数规范、签名认证可能全都合法，但行为已经彻底背离用户原始意图。

APASS 设置了多层交叉校验：

- **意图安全模型**：实时将当前交易动作与用户最初 Prompt 和核心约束进行语义对齐，识别“买 PPT 素材变成买数码硬件”“买水变成买黄金”等严重意图漂移；
- **执行链路监控**：持续监测工具与 API 调用，提供进程级安全隔离，防止未授权权限跃迁；
- **资金风控模型分级处置**：规则网格内的常规采买静默放行；边界模糊的调用暂缓并短信/电话确认；判定为高危恶意偏离时，底层阻断交易并推送安全警报。

关键在于，不仅要在“支付接口”层面校验，更要在“语义意图”和“执行过程”层面校验。

### 5. 责任归属：模型幻觉、商家履约与账户盗用是三类问题

当一笔智能体参与的交易办砸了，最可怕的不是损失，而是各方互相踢皮球：支付方推给模型方，模型方推给外部网页，商户推给自动下单代码。

文章区分了三种典型场景：

- **账户或 Agent 被盗用**：属于资金安全风险，适用“你敢付，我敢赔”，但需用户开启相应安全能力并符合条件；
- **模型理解偏差**：例如把上午航班买成红眼航班，收银台协议完好，问题出在认知偏差，应由智能体服务平台介入核查；
- **商户履约质量纠纷**：例如模板压缩包损坏，属于传统电商售后退款与仲裁范畴。

APASS 不负责“自动断案”，而是通过**可信存证**充当“飞行黑匣子”：留存用户授权内容、运行环境核验结果、服务调用、交易与处置记录，为事后追溯和纠纷处理提供依据。

### 6. 跨平台互信：单点安全无法支撑复杂智能体商业

当 Agent 需要跨平台调用云数据库、云服务器、支付服务等不同服务商时，如果每家都做定制化鉴权，协作成本极高。

APASS 提供的是**通用信任核验接口**：

- 云服务商可以通过 APASS 直接核实 Agent 的责任主体、Scope 是否覆盖本次调用、实时风险等级；
- 助手平台掌握用户意图，支付与安全机构掌握交易风险数据，双方基于隐私保护机制联合风控，**原始数据互不出域**；
- 通过产品接入与生态共建，推动身份互认与信任协作。

目前 APASS 已接入 **超过 100 万个 Agent，激活量 11 万个，覆盖 442 家智能体服务供给方**；包括阿里巴巴、小米、OPPO、联想、携程、中国信通院等 **50 余家机构**已加入 IIFAA 智能体可信生态共建计划。国际上，Alipay+ AMP、Mastercard 可验证意图、Visa 智能体可信协议也在推动 KYA 互联互通。

## 启发与影响

### 对行业格局

- **信任基础设施可能成为智能体商业的“新支付层”**。过去移动互联网的竞争围绕流量与支付入口，而智能体时代的竞争可能上移到“身份核验、授权策略、意图风控、责任存证”这一整套信任底座。
- **支付与安全机构有机会成为中立枢纽**。因为它们天然掌握交易风险数据，又具备与银行、商户、监管协作的经验，能在跨平台 Agent 商业中扮演信任中间层。

### 对开发者与服务商

- **身份与授权标准化将降低接入成本**。如果 KYA/Scope 风格的标准普及，Agent 开发者不需要为每一家商户做定制鉴权，而可以把精力集中在任务能力上。
- **“责任主体清晰”将倒逼 Agent 平台规范化**。谁部署、谁运营、谁负责，会被纳入商业准入条件，而不再只是一个技术细节。

### 对企业与用户

- **用户从“敢用”到“敢托付”的关键是可追溯的委托边界**。就像管理者放权不是盲信下属，而是因为权限清晰、过程可监督、出事可追责。
- **推理成本与安全体验的平衡会成为产品竞争力**。过于频繁的身份验证会杀死智能体价值，但完全不设防则无法进入高价值交易场景。

### 对监管与标准

- **KYA 与 KYC/KYB 的融合是必然方向**。Agent 不是法律主体，必须映射到现实责任主体。
- **跨生态与国际协议对接已启动**。Visa、Mastercard、Alipay+ 的参与表明，智能体信任标准可能比预想更快进入跨境商业基础设施层面。

---

**一句话总结：**  
智能体要真正替人花钱，先要证明“它是谁、能做什么、有没有跑偏、出了事找谁”。APASS 及其代表的 KYA 信任基础设施，正在把这四个问题变成可验证、可执行、可追溯的工程问题，这是 AI 从对话框走向商业深水区的第一块基石。
