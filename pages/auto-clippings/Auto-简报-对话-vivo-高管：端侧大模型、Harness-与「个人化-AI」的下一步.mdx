# vivo「个人化 AI」战略简报：端侧大模型、Harness 与系统接口革命

&gt; **来源**：爱范儿 ifanr  
&gt; **原文链接**：https://www.ifanr.com/1680321?utm_source=rss&utm_medium=rss&utm_campaign=

&gt; **主题**：vivo 如何将 AI 从单点功能升级为系统底座，构建「个人化智能」

---

## 核心摘要

vivo 在开发者大会上发布「个人化智能」，核心逻辑不再是单点 AI 功能，而是让 AI 成为操作系统的一部分：

&gt; **端侧模型负责理解个人信息，Harness 负责任务调度，6000+ 原子能力作为可编排工具，个人上下文提供长期记忆。**

战略关键判断：**模型可以替换，Harness 与个人上下文才是真正护城河**；MoE 让 30B 端侧模型成为可能，但真正成熟要等到 2028 年前后；对 GUI Agent 保持克制，优先让应用本身「Agent Ready」；跨端办公则定位为用手机个人数据遥控 PC 生产力。

---

## 1. 30B 端侧模型：MoE 改变可行性，成熟在 2028

- **一年前的判断**：手机跑 7B 模型已吃力，13B 几乎不可行。原因是模型加载需占用 4GB 以上内存，而旗舰手机主流只有 12GB 左右。
- **MoE 成为转折点**：混合专家模型无需每次推理加载全部参数。30B 模型拆成大量专家，按需调度少数几个，动态内存占用仅 2–4GB；未激活参数可存放在 512GB/1TB 闪存中。
- **现状**：30B MoE 模型仍处**工程验证阶段**，尚未进入消费级手机。
- **新瓶颈**：专家之间搬运、芯片调度、功耗控制、端侧算力配置。
- **时间预期**：整套能力成熟约在 **2028 年前后**。届时高端手机仍大概率维持 12–16GB 内存，长期划拨给端侧模型的常驻空间约 4GB。

---

## 2. Harness：不挑模型的执行中枢

- **定位**：大模型是「大脑」，Harness 是「执行中枢」。模型负责理解意图，Harness 负责维护任务循环（main loop）、寻找工具、调取上下文、执行能力、校验结果。
- **复杂任务**：可能出现 main loop 套 main loop、Harness 管理多个 Harness 的情况。vivo 已将 Harness main loop 嵌入蓝心小 V，甚至进一步嵌入系统进程。
- **核心判断**：
  &gt; **「Harness 本身是不挑模型的。」**

  底层可替换 DeepSeek、Claude 或其他模型，真正需要长期保留的是 **执行逻辑、上下文和用户记忆**。
- **换机迁移**：模型重新下载即可，真正需要无缝迁移的是**感知记忆、长期习惯、个人上下文**。

---

## 3. 个人化智能的差异化壁垒

vivo 将个人 AI 差异总结为两点：

1. **端侧 Harness 能深入调度整个 OS**；
2. **手机拥有用户个人专属的上下文**。

- **隐私与效率**：手机 24 小时贴身，沉淀照片、日历、位置、设备状态。如果每次等用户提问再上传云端分析，效率低且触碰隐私红线。因此 vivo 强调**让端侧模型提前理解**，让「AI 走在人前」。
- **相册搜索案例**：要找「国庆节带小孩去海边」的照片，端侧模型平时已在后台理解照片并记录特征，真正搜索时 AI 已知道大概位置。
- **旅游攻略案例**：普通 AI 规划行程需要用户反复交代家人身体状况；个人化智能则通过长期感知记住家庭关系，自动放缓节奏，甚至提醒「带上折叠小马扎，方便孕妻随时坐下歇脚」。
- **价值主张**：
  &gt; 「惊艳的，从来不仅是 AI 规划路线的算力，而是它长年累月掌握了你的家庭羁绊、社会关系、行为偏好与时空轨迹，并将这些带着温度的背景，无缝注入 Harness 与大模型的每一次执行中。」

---

## 4. 6000+ 原子能力：拆掉 App 柏林墙

- **原子能力定义**：App 内可被独立剥离、单独调用的最小功能单元。例如笔记写入、格式转换、创建日历、修改系统设置。
- **来源**：目前七八成来自 vivo 官方系统应用，过去深藏于多层 UI 页面之后。
- **交互范式变化**：
  - 过去：**用户 → App → 页面 → 按钮 → 功能**
  - Agent 时代：**Agent → Tool → 功能**
- **Skill 封装**：高频组合能力会被进一步封装为 Skill，避免每次从零件重新拼装。
- **第三方接入**：不设格式限制，兼容 MCP、A2A、CLI 等协议，唯一标准是**对 Agent 工作更友好、更高效**。
- **生态目标**：打破 App 孤岛，建立新的系统接口层，让所有能力汇入 Harness 可调用的工具池。
- **未来规模**：6000+ 只是起点，周围预计完整支持 PC 上各 Harness 可能需要 **2–3 万个 Skill 和接口**，蓝河已在推进。

---

## 5. GUI Agent：克制与兜底

- **态度**：vivo 内部对 GUI Agent 相当保守。
- **原因**：执行效率不高；界面改版易导致链路瘫痪；复杂任务微小偏差会雪崩；涉及支付、隐私时风险放大。
- **长期判断**：部分应用界面会走向极简甚至弱化，沦为纯后台信息服务。训练 AI 死记「该点哪个按钮」，长期价值会被稀释。
- **策略**：优先让 App 本身逐渐 **「Agent Ready」**。例如日历模块能直接感知系统事件并完成创建，AI 无需模拟人的手指。
- **GUI 定位**：作为长尾场景兜底方案，如支付宝部分政务、生活服务。未来 MCP、Skill、Agent、A2A、GUI 多种范式将并存。

---

## 6. 跨端办公：手机做 PC 的「超级遥控器」

- **小 V Co-work 定位**：不是让手机死磕重度代码或文档生产，而是做 PC 的**控制面板**。
- **使用场景**：用户远离 PC 时，仍可通过手机遥控工位或家中电脑上的 Agent 任务。
- **差异化底气**：**个人上下文最全的地方在手机上**。用户在使用各类智能体时总需反复交代背景，而 vivo 可直接将手机中的个人上下文注入 Harness，远程调用 PC 工具时无需重复解释。
- **结论**：
  &gt; 「纯粹拼 PC 端算力或云端模型，手机厂商未必有绝对优势，但用最全的个人数据去『遥控』生产力，成了 vivo 破局的思路。」

---

## 7. 双 OS 路线

- **OriginOS 7**：在成熟智能手机形态上叠加 AI 能力。App、桌面、交互仍保留，但 AI 多了一条深入系统内部完成任务的通路。
- **蓝河智能体操作系统技术预览版**：更激进，用 Rust 打通内核、系统框架与应用；在蓝河 OS Harness 中提供 Shell、Python 等工具，探索基于任务的跨应用最小化授权。（原文在此处截断，后续细节未展示）

## 分析师简评

vivo 的战略本质，是**用「个人上下文 + 系统级 Harness + 原子化工具生态」建立 AI Phone 的护城河**，而非依赖单一模型或单个 App。在模型能力趋同的背景下，系统调度能力、端侧隐私化的个人记忆、以及可编排的第三方服务接口，构成三重壁垒。

值得注意的是，vivo 对 GUI Agent 的克制态度，表明其更相信结构化接口而非视觉模拟。这可能影响第三方生态的接入方式，也意味着未来竞争将更多转向**系统接口层的开放度与效率**。

关键观察节点：
1. **2028 年前后**端侧 30B MoE 模型能否在 4GB 常驻内存限制下成熟落地；
2. **数万级 Skill/接口**建设进度，以及第三方应用是否愿意「Agent Ready」；
3. 蓝河 OS 能否从技术预览走向规模化，承载更原生的 Agent 环境。

**风险提示**：第三方接入意愿、跨应用最小化授权安全、端侧模型硬件落地进度，以及 GUI 与结构化接口之间的生态博弈，将是后续重点。
