【帖子标题】：我们是否应该统一文档字符串格式？

【帖子正文】：
在 Rust 中，文档字符串相当正式化。它们是使用 markdown 编写的，并且甚至有一些标准的标题（如带有 # Errors 或 # Panics 部分）。这种形式的好处在于它允许像 docs.rs 这样的网站为任何项目构建文档页面而无需与不同的工具交互。此外，这使得 LSP 只需一种方式显示文档提示。

在 Python 中，我们有几种竞争的标准。NumPy 样式的文档字符串可能是使用最多的，但还有 Google 的格式以及几种不同的 reST 格式。这些很好，我们可以设置一些 lints 来确保文档字符串遵循标准。然而，在我看来（请随意反对），一个单一的 markdown 格式标准将帮助新手编写漂亮的文档字符串，使 PyPI（或其他供应商）能够构建自动化的文档站点，并为 LSP 和 IDE 提供如何显示文档的指导。这将包括链接的标准以及可能需要包含一些 mathml/LaTeX/KaTeX 支持。另一个好处是工具可以更好地支持自动化文档生成和自动补全，因为它们不需要猜测您遵循的是哪种标准。

我想听听大家对此的看法。我正考虑制定一个 PEP，但这可能是过度了（或者你们所有人都会讨厌这个想法）。我认为主要的阻碍将是采纳率，大型项目可能需要转换文档字符串，因此要么需要一些工具支持，要么可以有选择性地采用或不采用。如果这是一个糟糕的想法，请告诉我，但请友好些！

编辑：到目前为止，我们得到了大约 67% 的赞同票，这多少是预期之中的结果。我想澄清一下，并不是说我们应该阻止不符合此标准的文档字符串。我在评论中提到了锁定文件标准化的事宜，但这并不妨碍您编写具有自定义锁定文件的工具，只是已经有一个被广泛接受的标准格式作为首选方式。这就是我的想法。
