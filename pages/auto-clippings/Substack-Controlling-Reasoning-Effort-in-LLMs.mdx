# 📰 Controlling Reasoning Effort in LLMs

**来源**: Ahead of AI
**链接**: https://magazine.sebastianraschka.com/p/controlling-reasoning-effort-in-llms

## 📝 核心主旨 (TL;DR)
本文系统拆解了当代旗舰级推理大模型如何实现对“推理算力/Tokens消耗”的精细化控制。核心结论是：推理模式并非依赖神秘架构，而是通过后训练阶段（SFT/RLVR）的条件化微调与推理期的提示词/模板调度共同固化的**推理期算力扩展（Inference Scaling）**手段。通过调节长度惩罚、外部截断预算或交互式开关，开发者可在固定模型权重下灵活权衡延迟、API成本与任务精度，且各头部厂商已跑通多条差异化但底层逻辑互通的工程路线。

## 💡 关键知识点 / 核心观点
1. **推理轨迹的本质与 `&lt;think&gt;` 标签的误导性**：现代“推理模型”的核心特征是输出中间思维链（CoT）。训练主要依赖 RLVR（可验证奖励强化学习），奖励仅绑定最终答案正确率与格式合规性。模型在纯终态奖励下能自发学会回溯与自我修正（“Aha moments”）。`&lt;think&gt;` 标签仅是 UI 分隔符与格式约束，由 RLVR 阶段的规则奖励强行塑造；移除该标签不会损失模型的真实推理基准能力。
2. **性能提升的双轴模型：训练缩放 vs 推理缩放**：提升模型表现存在两个正交维度。① 训练缩放：更换参数量更大、训练预算更高的独立模型底座；② 推理缩放：冻结模型权重，在调用时分配更多/更少的计算 Token。推理努力度（Effort Level）属于后者。数据表明，提高努力度会线性拉升 Token 消耗与 API 成本，但准确率增长遵循明显的边际收益递减规律，需寻找性价比拐点。
3. **多档推理力度的工程落地三件套**：主流方案均将努力度映射为系统提示词（如 `Reasoning effort: low/high`）或对话模板参数，并通过以下技术栈固化行为：
   - **RLVR 动态代价调制**：在强化学习阶段，根据指令动态修改单 Token 的长度惩罚系数（低努力度=高惩罚强制精简；高努力度=低惩罚允许自由展开）。
   - **SFT 意图对齐**：构造 `{prompt_label} → {target_trace}` 配对数据集进行监督微调，使模型直接学习“标签-推演长度”的映射关系。
   - **混合训练管线**：通常先完成核心推理 RLVR，再叠加 Thinking Mode Fusion SFT，最后用通用 RL 巩固格式遵循能力。
4. **头部项目的差异化架构实践**：
   - **Qwen3 / GPT-oss 系**：采用“软硬双开关”。软开关依赖 SFT/RL 融合训练支持指令切换；硬开关直接在请求流中预填空 `&lt;/think&gt;&lt;/think&gt;` 块，物理阻断推理分支直接输出答案。
   - **DeepSeek V4**：前期并行训练 Non-think / Think High / Think Max 三个独立专家路由，配置不同的 Context Window 与 Length Penalty，最终通过 On-policy Distillation 合并为单模型，依靠强系统指令触发极致模式。
   - **NVIDIA Nemotron 3 Ultra**：引入“硬性推理预算（Hard Budget）”。推理端由 Chat Client 监控 Token 计数并主动闭合推理块；训练端使用随机截断的思维链数据（Mask掉插入的结束符），强制模型掌握在中断状态下接续推导并落地的能力。
   - **Moonshot Kimi K2.5**：设计 Toggle 交替训练策略，在 RL 迭代中周期切换“严格预算约束”与“全量生成长度”阶段，有效防止模型为迎合短预算而退化，保留长程复杂推理的上限。
