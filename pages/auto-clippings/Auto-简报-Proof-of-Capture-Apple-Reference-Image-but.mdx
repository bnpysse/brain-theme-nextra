# 精华简报：Proof of Capture——从“事后检测”到“捕获时证明”

## TL;DR

本文作者介绍了一个与 Alex Hornstein 合作开发的开源相机项目“Proof of Capture”，其核心不是事后识别 AI 造假，而是在照片被拍摄的瞬间，利用隐写术将签名的感知哈希嵌入图像像素中，并由 ATECC608 安全芯片完成签名，从而在压缩、分享、元数据被剥离后仍能验证照片“确实来自相机”。文章借此对比了 Apple 新推出的 Reference Image 方案，指出 Apple 虽方向类似，但信任根封闭在 Private Cloud Compute，且未采用 C2PA 开放标准。作者认为，这类方案都无法完全阻止“屏幕攻击”等绕过手段，但低成本开源实现和巨头入场标志着内容真实性验证正在从检测范式转向捕获时证明范式。

---

## 一、核心观点与技术/商业洞察

### 1. 检测与生成的军备竞赛注定失败，必须翻转问题

作者早在 2019 年部署 ML 事实核查工具时就意识到：**生成器的进步永远快于检测器**。检测器每次升级，都会成为下一代生成器的训练信号。因此，与其在事后判断“什么是假的”，不如在捕获时刻证明“什么是真的”。

这一判断是整篇文章的战略核心。它意味着内容真实性行业的竞争焦点，将从“模型检测能力”转向“硬件信任根 + 捕获时签名”的基础设施建设。

### 2. 真正的难点不在密码学，而在内容生命周期

作者指出，技术层面并不复杂，复杂的是如何处理**照片编辑**和**元数据剥离**两大现实问题：

- 用户裁剪照片后，签名是否仍然有效？
- 图片一旦分享，EXIF 等元数据常因隐私原因被平台自动删除，任何存储在元数据里的签名都会丢失。

因此，Proof of Capture 选择**隐写术**：将签名直接隐藏在图像像素本身中，而不是存放在元数据里。这样签名与内容绑定，不依赖外部信息。

### 3. 从精确哈希到感知哈希：一次关键的技术进化

项目第一版将精确 SHA-256 哈希隐藏在每像素的最后一位，结果任何 JPEG 重新压缩都会彻底破坏签名。这暴露了一个矛盾：**精确哈希过于脆弱，无法适应正常的图片处理和分享链路**。

第二版改为签名**感知哈希（pHash）**，并通过频域水印（DWT + DCT）将签名分散到整幅图像。这使得：

- 签名能存活 WhatsApp 级别的压缩和尺寸调整；
- 仍能检测出对画面内容的实质性编辑，因为感知哈希代表“照片看起来是什么样子”，而非“字节是否完全一致”。

这一进化说明：**内容真实性验证必须在鲁棒性与敏感性之间找到平衡**——既要容忍正常压缩，又要发现语义级篡改。

### 4. 硬件信任根：ATECC608 芯片

签名由自焊接的 ATECC608 密码芯片完成。该芯片持有公钥用于验证、私钥用于签名，私钥一旦生成就**永远无法被读取，包括设备所有者**。任何物理篡改都会导致芯片自锁。

这意味着信任不依赖软件、云服务或厂商承诺，而是建立在不可导出的硬件密钥上。项目总成本低于 100 美元，显著降低了去中心化信任根的门槛。

### 5. Apple Reference Image 的路线与争议

文章将 Apple 的新方案与自己的项目进行对比：

| 维度 | Proof of Capture（开源） | Apple Reference Image |
|---|---|---|
| 签名位置 | 嵌入像素内（隐写术） | 传感器签名每个像素，但发展为“数字负片”，与照片并存 |
| 信任根 | ATECC608 芯片，私钥不出芯片 | Private Cloud Compute，根信任在 Apple 私有云 |
| 标准兼容 | 未明确提及采用 C2PA | 未采用 C2PA，自建体系 |
| 验证流程 | 开源可审计 | 作者认为“尚未公开、不清晰” |
| 成本 | &lt;100 美元 | 依赖 Apple 生态 |

作者对此表达了明显不满：**Apple 未采用已被尼康、索尼、徕卡、Adobe 等采用的 C2PA 开放标准**。即便 Apple 开放 API 让平台原生验证，信任根仍然集中在 Apple 的私有云计算中。这意味着验证体系的最终权威是 Apple 而非开放生态，可能形成平台锁定和互操作性障碍。

### 6. 任何方案都无法完全解决“屏幕攻击”

作者坦率承认一个共同盲点：**屏幕攻击**。即对着显示 AI 生成图像的屏幕拍照，仍然可以得到一张“经过官方签名的真实照片”，但内容本身是假的。

因此，Proof of Capture、Apple Reference Image、C2PA 都只是降低了伪造门槛、提高了取证可靠性，并没有彻底解决内容真实性问题。作者认为，即便如此，大玩家入场仍值得肯定。

## 二、对行业的启发与影响

### 1. 内容真实性产业正从“事后检测”转向“捕获时证明”

文章清晰地标志了一个范式转移：继续提高 AI 图像检测器的准确率是一条没有尽头的路。未来更有价值的赛道，是在相机、手机等捕获设备端植入安全芯片和签名机制，使真实内容从出生起就携带可验证凭证。

### 2. 开放标准与封闭生态可能形成路线分裂

Apple 不采用 C2PA，而是通过 Private Cloud Compute 建立自己的信任体系，可能产生两种后果：

- **推动主流用户关注内容来源**，加速行业教育；
- **制造标准分裂**，导致不同平台验证互不兼容，削弱整体可信度。

对行业参与者而言，支持 C2PA 等开放标准，或在封闭方案之外提供互操作接口，将成为竞争关键。开源项目证明，低成本硬件即可以绕过中心化信任根。

### 3. 隐写术 + 感知哈希在消费级场景中具备实用潜力

传统数字签名过于脆弱，无法承受社交平台的压缩和格式转换。Proof of Capture 展示了**将签名绑定到感知内容而非精确字节**的可行性。这对媒体平台、图片库、新闻机构在分发链路上验证图片来源，具有直接借鉴意义。

### 4. 硬件安全模块将成为内容信任基础设施

ATECC608 等低成本安全芯片可能像摄像头、麦克风一样成为消费级设备的标配。其“私钥不可导出、防篡改自锁”的特性，为去中心化的内容溯源提供了硬件基础。相机、手机、甚至专业影视设备厂商，都可以在供应链中集成类似模块。

### 5. 残余威胁要求技术之外的综合治理

屏幕攻击的不可解性说明，技术方案只能回答“这张照片是否由真实相机拍摄”，无法回答“拍摄对象是否真实”。因此，行业还需要配套：

- 平台层面的传播链路追踪；
- 新闻机构的采编流程审计；
- 用户媒介素养教育；
- 针对伪造内容的法律与政策约束。

## 总结

这篇文章的价值在于：它不是一个纯理论设想，而是一个可运行、低成本、开源的工程实现；同时以实践者视角对 Apple 的 Reference Image 方案提出了具体批评。核心信号是：内容证明的竞争起点正在从“更好的检测模型”转向“更可信的捕获硬件与更开放的验证协议”。谁能建立兼容性最强、信任根最透明的生态，谁就更有可能掌握数字内容真实性的下一阶段标准。
