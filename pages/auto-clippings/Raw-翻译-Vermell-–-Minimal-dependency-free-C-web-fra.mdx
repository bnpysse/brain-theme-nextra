【文章标题】：Vermell – 基于epoll的极简、无依赖C++ Web框架

【文章正文】：
一个专为现代C++环境设计的极简、零膨胀Web框架。快速、结构化且强类型。
Vermell是为现代C++环境打造的Web框架：只需包含一个头文件，链接一个静态库，别无其他。没有运行时、没有垃圾回收器、没有框架专属DSL、没有第三方依赖——你写的是C++，运行的也是C++。
其核心是事件驱动引擎：非阻塞的epoll循环读取请求，并将任务分配给工作线程池。这种分离设计使Vermell在高负载下保持高速，并能抵御慢速客户端攻击。
- 零依赖——仅需基础Linux API（套接字、epoll、pthreads、fork/exec）
- 单命令构建——g++ -std=c++20 server.cpp -o exe -lvermell
- 兼容所有带g++的Linux——x86_64、ARM（aarch64、armv7）、通过Termux的Android、WSL、树莓派、容器
- 默认强化防护——开箱即用超时控制、请求限制、连接数限制和渲染沙盒
- 内置JSON DOM——严格遵循RFC 8259的解析器/序列化器，支持类型化参数、原始正文和多部分上传
- C++模板——compose()模块和render()变量
- 流畅配置——通过configure(&#123;...&#125;)调用或链式设置器，支持运行时读取

router.listen()会阻塞并永久服务。listenOne()处理单次请求后返回——适合测试和一次性服务。

单条g++命令完成编译链接——无需额外标志或调整链接顺序：
$ g++ -std=c++20 server.cpp -o exe -lvermell

大型项目可用CMake，但服务器始终一键可建。

跨平台性。Vermell无依赖，任何衍生自Linux且支持C++20 g++的环境均可构建：x86_64、ARM（aarch64、armv7）、通过Termux的Android、WSL、树莓派、容器。不支持macOS和Windows（因epoll限制）。

无root权限？不成问题。Termux（或其他无root系统）无法安装到/usr/local。通过相对路径包含头文件（#include "../include/vermell/vermell.h"）并直接链接静态库——将libvermell.a复制到源码旁，编译时添加-L. -lvermell：

// Termux/无root构建：通过相对路径引用头文件
#include "../include/vermell/vermell.h"

    router.get("/", &#123; [](Query &http) &#123;

    &#125;&#125;);

$ cp libvermell.a .          # 静态库与源码同目录
$ g++ -std=c++20 server.cpp -o exe -L. -lvermell
$ ./exe
