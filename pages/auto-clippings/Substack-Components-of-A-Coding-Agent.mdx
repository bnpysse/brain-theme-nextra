# 📰 Components of A Coding Agent

**来源**: Ahead of AI
**链接**: https://magazine.sebastianraschka.com/p/components-of-a-coding-agent

## 📝 核心主旨 (TL;DR)
现代代码AI工具（如Claude Code、Codex CLI）的实际效能并非仅由底层大模型决定，而是高度依赖于外层的 **“Coding Harness（编码代理脚手架）”**。该架构通过稳定的上下文预加载、结构化工具执行沙箱、抗膨胀的记忆管理机制与迭代控制循环，将基础LLM转化为具备真实软件工程闭环能力的生产级系统；在底座模型能力日益同质化的当下，Harness的系统设计质量已成为拉开产品体验差距的核心分水岭。

## 💡 关键知识点 / 核心观点
1. **厘清技术分层：LLM vs 推理模型 vs Agent vs Harness**
   - `LLM`是底层词元预测引擎；`推理模型`是在此基础上经过训练/提示优化，能投入更多推理时间进行中间验证与自我检查的增强版引擎；`Agent`是基于模型的决策控制循环（观察→分析→决策→执行）；`Harness`则是包裹Agent的工程软件栈，负责Prompt组装、工具暴露、状态追踪、缓存管理与权限控制。优秀Harness能显著提升非推理模型的工程表现。
2. **Workspace Context预采 + Prompt前缀缓存复用**
   - 代理启动时需先采集“稳定事实”（Git仓库根目录、当前分支、`AGENTS.md`/README规范、项目结构等）作为初始上下文。为避免每轮重复解析，Runtime会将这些不常变动的内容打包为 `Stable prompt prefix` 进行缓存；后续交互仅动态追加变化部分（最新指令、短期记忆、最近几轮对话）。此举大幅节省计算资源，保障长会话的上下文一致性与响应速度。
3. **结构化工具调用与安全边界管控**
   - 代码代理从“纯生成”转向“行动型”，依赖预定义的工具集（列出文件、读取、搜索、运行Shell、写入等）。模型输出结构化动作后，Harness必须在执行前进行程序化校验：工具是否注册、参数类型是否合法、目标路径是否在沙箱白名单内、是否触发高危操作需人工审批。这种“牺牲自由度换取确定性”的设计是避免破坏性误操作的前提。
4. **防Context Bloat与双层记忆架构设计**
   - 多轮代码编辑会产生大量日志、Diff和重复文件读取，极易耗尽上下文窗口。高效Harness采用组合压缩策略：① 实时裁剪（Clip）超长片段；② 去重旧版本文档；③ 按时间衰减压缩历史记录（保留近期高保真信息，合并早期事件）。同时，状态管理拆分为两层：`Compact Transcript`（面向下一轮Prompt重建，强调时效性与紧凑性）与 `Working Memory`（面向跨轮次任务连续性，持久化维护当前目标、关键文件指针与阶段性结论）。
5. **受控委派（Bounded Subagents）实现安全并行**
   - 当主代理需要处理异步查询或副作用较小的子任务（如定位符号定义、查看特定配置、调试失败测试）时，可派生子代理并行处理。核心难点在于“边界绑定”：子代理必须继承足够的领域上下文才能有效工作，但必须被严格约束（如默认只读模式、最大递归深度限制、作用域隔离、终止条件设定），防止任务重叠、文件竞态或失控嵌套，从而在可控风险下提升整体吞吐量。

## 🏷️ 提及的重要概念/公司/模型
- **核心架构/概念**：Coding/Agent Harness（代理脚手架）、Agentic Control Loop（代理控制循环）、Context Compaction & Bloat（上下文压缩/膨胀）、Prompt Prefix Caching（Prompt前缀缓存）、Structured Tool Calling（结构化工具调用）、Bounded Subagents（有界子代理）、Working Memory vs Full Transcript（工作记忆与完整会话记录）
- **代表平台/工具**：Claude Code, Codex CLI, Mini Coding Agent (作者开源参考实现), OpenClaw
- **模型与架构术语**：LLM (Large Language Model), Reasoning Model (推理模型), Next-token Prediction, Intermediate Reasoning Traces, Attention Variants
- **关键文件/规范**：`AGENTS.md`, `SOUL.md`, `TOOLS.md`, Workspace Summary, Git Branch/Status
