# Brave 浏览器性能优势简报

**来源**：Solidot（奇客科技与极客资讯）  
**链接**：https://www.solidot.org/story?sid=85324

## TL;DR

Brave 官方发布了一组基准测试，声称其桌面版浏览器在 CPU 占用、内存消耗和页面加载速度上均明显优于 Chrome、Microsoft Edge 和 Firefox。但该测试使用了旧版 Firefox（v146.0.1 而非最新 v155），且属于厂商自测，测试环境与条件未充分披露，因此结论具有一定参考价值，但也需要第三方独立评测进一步验证。

## 核心观点与技术/商业洞察

### 1. 性能对比数据

Brave 公布的测试结果如下：

| 浏览器 | 平均 CPU 占用率 | 内存占用 | 页面加载时间 |
|---|---:|---:|---:|
| Brave | 33% | ~1.2 GB | 4.4 秒 |
| Chrome | 47% | ~1.75 GB | 5.1 秒 |
| Edge | 53% | ~1.62 GB | 6.0 秒 |
| Firefox | 78% | ~1.65 GB | 5.3 秒 |

从数据看，Brave 在三个维度上均领先。尤其在 CPU 占用率上，Brave 比 Firefox 低 45 个百分点，内存占用比 Chrome 低约 0.55 GB，加载时间比 Edge 快 1.6 秒。

### 2. 内置广告屏蔽是性能优势的关键

Brave 将性能优势主要归因于其内置的广告与跟踪器屏蔽功能。拦截广告和跟踪脚本可以显著减少：

- 网络请求数量
- JavaScript 执行时间
- DOM 节点渲染负担
- 第三方资源加载与 Cookie 同步

这意味着，Brave 的性能优化不仅是工程层面的调优，更是一种“默认干掉重负载内容”的策略。它把隐私保护与性能提升绑定，形成了差异化卖点。

### 3. 测试方法存在明显瑕疵

该测试的可信度受到几个因素影响：

- **Firefox 使用旧版本**：测试采用的是 Firefox v146.0.1，而非文章发布时的最新版 v155。旧版本可能缺少性能优化，导致 Firefox 的 CPU 占用率高达 78%，显得格外落后。
- **测试环境不透明**：未披露硬件配置、操作系统、网络环境、测试页面样本、缓存策略、是否禁用其他扩展、是否为冷启动或热启动等关键信息。
- **厂商自测利益冲突**：由 Brave 自行发布的数据，可能存在选择性展示或条件设置有利于自身的风险。
- **指标定义模糊**：“平均 CPU 占用率”如何采样、是否包含空闲状态等细节不明确，可能影响可比性。

因此，这组数据更适合视为 Brave 的市场宣传，而非严格的第三方性能评测。

### 4. 商业动机与竞争策略

Brave 通过性能测试塑造“轻量、快速、省资源”的品牌形象，目标用户群体明确：

- 低端笔记本电脑或老旧设备用户
- 习惯同时打开大量标签页的重度用户
- 关注系统资源消耗与电池续航的用户
- 注重隐私但又不想牺牲性能的用户

这种策略旨在从 Chrome、Edge 和 Firefox 手中争夺对性能敏感的用户群体。由于 Brave 本身基于 Chromium 内核，它与 Chrome/Edge 在底层兼容性上接近，但通过内置广告屏蔽实现了“同源但更轻”的体验差异。

### 5. 浏览器竞争维度扩展

过去浏览器竞争主要围绕速度、兼容性、隐私和安全。如今，系统资源占用（CPU/内存）和加载效率成为新的核心竞争维度。随着 Web 应用日益复杂，浏览器“变重”的问题越来越突出，资源效率直接影响用户体验和设备功耗。

## 对行业的启发与影响

### 对浏览器厂商

- Brave 的做法可能促使 Chrome、Edge 和 Firefox 更加重视资源占用优化，甚至考虑默认提供更强的跟踪器拦截或“轻量模式”。
- Chrome 和 Edge 长期被部分用户认为“内存占用高、耗电”，这组数据可能加深这一认知，迫使它们加强性能优化或改进宣传策略。
- Firefox 应确保在第三方对比测试中使用最新版本，避免因版本过旧而吃亏；同时也应强化自己在隐私与性能平衡上的技术叙事。

### 对评测机构与媒体

- 该事件凸显独立、标准化基准测试的重要性。行业需要统一的测试协议，包括固定硬件、浏览器版本、页面样本、网络延迟、冷/热启动条件等。
- 媒体在转述厂商自测数据时，应明确标注“厂商数据、未经独立验证”，避免误导读者。

### 对内容与广告生态

- Brave 默认拦截广告的做法虽然提升了性能与隐私，但可能进一步加剧浏览器厂商与依靠广告收入的内容创作者、出版商之间的商业模式冲突。
- 如果“广告屏蔽=性能提升”的观念被广泛接受，可能推动更多用户启用广告拦截，对开放互联网的广告生态造成更大压力。

### 对用户与企业决策

- 用户在选择浏览器时，不应只根据厂商公布的基准数据做决定，还应考虑扩展生态、同步便利性、安全更新、隐私政策、网站兼容性以及实际工作负载下的表现。
- 企业 IT 部门在评估浏览器时，应进行内部测试，模拟真实业务场景，而不是仅参考厂商宣传。

### 对技术演进

- 广告屏蔽从隐私功能演变为性能优化手段，提示浏览器厂商可以通过减少不必要的第三方请求来提升整体体验。
- 未来可能出现更多“资源感知型”浏览器功能，例如智能拦截、休眠后台标签、按需加载脚本等，进一步降低系统负担。

## 总结

Brave 的性能优势宣传具有一定数据支撑，但测试方法上的瑕疵（尤其是使用旧版 Firefox）削弱了其客观性。这一事件反映了浏览器市场从“功能竞争”转向“效率竞争”的趋势，也提醒行业与用户在看待厂商自测数据时保持审慎。真正有说服力的结论，仍需依赖独立、透明的第三方评测。
