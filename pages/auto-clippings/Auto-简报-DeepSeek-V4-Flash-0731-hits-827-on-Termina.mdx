### 技术情报简报：DeepSeek V4 Flash 0731 独立评测复现与分析

#### 💡 TL;DR (核心信息总结)
Ante 测试框架作者通过独立、公开的测试环境，成功复现了 DeepSeek V4 Flash 0731 在 Terminal-Bench 2.1 终端任务基准上 82.7% 的官方成绩，并开源了包含 445 次试验的完整底层运行数据，同时揭示了该模型对评测框架（Harness）配置具有较高敏感性的技术特征。

---

#### 🔍 核心观点与技术细节

*   **官方成绩获独立交叉验证**：DeepSeek 官方报告的 82.7% 成绩使用的是尚未公开的“DeepSeek Harness minimal mode”。本次独立测试使用公开的 Ante 0.preview.71 框架，在 445 次试验中取得 368 次成功，准确率精确达到 82.7%（±1.79 标准误差），证实了官方数据的真实性。
*   **严谨的大规模实验设计**：测试覆盖了 Terminal-Bench 2.1 的全部 89 项任务，每项任务进行 5 次重复试验（共计 445 次）。测试条件设定为“最大推理努力（max inference effort）”且“未启用任何外部技能（no skills enabled）”，模型通过 OpenRouter API 调用。
*   **极高的数据透明度与可复现性**：作者通过 Harbor 框架公开了完整的工作日志。数据不仅包含固定配置，还详细记录了所有 445 次试验的底层指标，包括奖励得分、异常报错、执行持续时间以及 Token 消耗量，为社区提供了极具价值的研究素材。
*   **揭示模型对评测框架的敏感性**：测试发现 DeepSeek V4 对测试框架（Test Harness）的具体实现较为敏感。这意味着不同的 Prompt 模板、系统指令或框架交互逻辑，都可能对最终得分产生显著影响。

---

#### 🎯 提炼的【核心痛点】

本次事件折射出当前大语言模型（LLM）评测领域的几个关键痛点：

1.  **评测框架“黑盒化”导致的成绩不可比性**
    官方在发布 SOTA（当前最佳）成绩时，往往使用内部或未公开的自定义评测框架（如本案中的“minimal mode”）。这种“黑盒”操作导致第三方开发者难以在完全一致的条件下进行公平对比，容易引发社区对成绩“注水”或“过拟合特定框架”的质疑。
2.  **模型对 Prompt/框架的过度敏感（评测鲁棒性缺失）**
    模型表现高度依赖于测试框架的配置，暴露出当前 LLM 在指令遵循和上下文理解上的“脆弱性”。如果模型能力严重绑定于特定的 Prompt 工程或框架结构，说明其泛化能力和鲁棒性仍有待提升，评测成绩可能反映的是“框架适配度”而非纯粹的“通用智能”。
3.  **评测过程缺乏细粒度的透明度与归因能力**
    大多数模型厂商在发布评测结果时，仅提供一个最终的聚合分数（如 82.7%），而不公开底层执行细节。缺乏如 Token 消耗、异常中断率、单次任务耗时等细粒度数据，使得研究人员无法深入分析模型失败的原因（是推理能力不足，还是上下文窗口溢出，或是工具调用失败），阻碍了技术的针对性迭代。
