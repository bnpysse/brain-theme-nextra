# 📰 Understanding and Coding the KV Cache in LLMs from Scratch

**来源**: Ahead of AI
**链接**: https://magazine.sebastianraschka.com/p/coding-the-kv-cache-in-llms

## 📝 核心主旨 (TL;DR)
KV Cache 是大语言模型自回归推理阶段的决定性加速技术。它通过在首步提示词编码后缓存历史 token 的 Key 和 Value 矩阵，彻底消除后续逐词生成时的重复 Attention 计算，将累计计算复杂度从 $O(n^2)$ 降至线性 $O(n)$。该技术在生产环境中可带来显著的推理提速（实测 CPU 端提升 5 倍+），但以显存占用随序列长度线性增长为代价，且仅限 Inference 阶段使用，是平衡计算效率与存储资源的核心工程实践。

## 💡 关键知识点 / 核心观点
1. **自回归生成的计算瓶颈与缓存原理**：LLM 每次生成新 token 时，若不采用缓存机制，整个前置历史序列都会被重新送入 Attention 模块计算 K/V 矩阵。KV Cache 的核心逻辑是“一次计算，多次复用”：仅在每轮传入新 token 时计算其对应的 K/V，并将其追加至缓存中；后续 Step 的 Query 直接检索缓存中的历史 K/V 进行点积运算，避免冗余算力浪费。
2. **从 Scratch 实现的关键代码模式**：
   - **状态持久化**：使用 `self.register_buffer("cache_k/v", None)` 注册 PyTorch Buffer，确保缓存张量能随 `model.to(device)` 自动同步至目标硬件。
   - **动态拼接与位置对齐**：在 `MultiHeadAttention.forward` 中引入 `use_cache` 开关。开启时通过 `torch.cat(dim=1)` 追加新 K/V，并在主模型层维护 `current_pos` 计数器，确保新输入的 Positional Embedding 与缓存中的历史位置严格对齐，防止因果注意力错位。
   - **隔离与重置**：不同 Prompt 间必须调用 `reset_kv_cache()` 清空缓冲区和位置计数器，否则模型会错误地将上一段文本的语境混入当前请求。
3. **算力与显存的经典 Trade-off**：序列越长，KV Cache 的收益越高。无缓存时，生成第 $t$ 个 token 需比较 $t$ 组 K/V，总计算量呈二次方爆炸；有缓存时，每步仅需计算 1 个 token 的 K/V，总计算量呈线性。代价是显存开销随生成长度线性膨胀，长上下文或大 Batch 下极易引发 OOM。该技术无法用于 Training，因为反向传播需要独立的梯度流而非静态缓存。
4. **生产级工程优化路径**：文章提供的教学代码侧重可读性，实际落地需解决两个痛点：
   - **内存碎片与分配延迟**：高频 `torch.cat` 会导致频繁的内存申请/释放。工业界标准做法是**预分配最大上下文张量**，推理时直接按偏移量切片写入（如 `cache_k[:, :, pos:pos+new_len, :] = new_k`）。
   - **显存封顶策略**：针对超长对话，采用**滑动窗口（Sliding Window）**或动态截断机制，仅保留最近 $N$ 个 token 的缓存，牺牲部分早期上下文依赖以换取可控的显存 footprint。
5. **大模型部署的硬件差异洞察**：在 Llama 3 / Qwen3 等支持超长上下文的模型上，盲目预分配会导致数 GB 的静默显存浪费。作者在实测中发现，对于超大 Context 模型，放弃预分配改用动态 `torch.cat` 并结合 `torch.compile` 编译，反而能在 CPU 端获得更优的实际吞吐；而在 GPU 端，由于 Kernel 启动开销和设备通信延迟，小模型上未优化实现的 KV Cache 优势会被掩盖。这强调了算法设计必须与底层硬件执行特性深度耦合。

## 🏷️ 提及的重要概念/公司/模型
- **核心技术与概念**: KV Cache (Key-Value Cache)、自回归解码 (Autoregressive Decoding)、注意力机制 (Attention Mechanism)、因果掩码 (Causal/Causality Mask)、计算复杂度 ($O(n^2)$ vs $O(n)$)、显存预分配 (Memory Pre-allocation)、滑动窗口截断 (Sliding Window Truncation)、位置编码对齐 (Positional Alignment)、`torch.compile` 图编译优化。
- **AI 模型架构/代表**: GPT 基础架构 (Transformer Blocks)、Llama 3 (1B 参数, 131k 上下文)、Qwen3 (0.6B 参数, 41k 上下文)。
- **开发框架与工具**: Python, PyTorch (`register_buffer`, `torch.cat`, `torch.no_grad`), Mac M4 Silicon (CPU Benchmark 环境), Diff Tools。
