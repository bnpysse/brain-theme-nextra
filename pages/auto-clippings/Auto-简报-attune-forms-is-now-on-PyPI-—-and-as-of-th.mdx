# 情报简报：attune-forms — 为 AI 智能体引入类型化表单通信语法

## TL;DR

attune-forms 是一个新发布的开源 Python 库（同时提供 Claude Code 插件形式），其核心理念是：**智能体提出的问题不应是自由文本句子，而应是类型化、可验证的结构化工件（artifact）**。该库为 AI 编程智能体在自由聊天之外开辟了"第二通道"——声明式、经过验证的表单机制，将独立的决策批量打包为一次往返（round-trip），而非连续二十次问答，且在构建阶段拒绝格式错误的提问、在收集阶段拒绝格式错误的回答，杜绝双向的静默接受。项目三天内从 v0.1.0 迭代至 v0.4.0，全流程自产自用验证。

---

## 核心观点与技术细节

### 设计哲学
- **形式化通信语法**：主张人机交互应具备类似 API 契约的语法规则——提问是"类型化的工件"，而非一句自然语言，从而消除歧义与隐式假设。
- **双向校验**：提问在构建时验证，回答在收集时验证，任何一方都不存在"静默接受"的灰色地带。
- **降级不崩溃**：同一套 schema 适配三种宿主环境（HTML 交互组件 / 终端批量文本 / 原生 MCP 引导），环境能力不足时自动降级，但功能不失效。

### 三种核心语义结构（承载对话性含义）
| 结构 | 功能 | 关键特性 |
|------|------|----------|
| **Decision（决策）** | 智能体提出方案 | 推荐选项置顶、附"为什么"理由、每个备选方案下有一行利弊权衡 |
| **Pushback（反驳）** | 结构化异议 | 用户方案与智能体替代方案并排对比；否决智能体是"一等公民"结果而非失败 |
| **Progress（进度）** | 状态报告 | 被阻塞项直接变成选择器，**阅读状态与解除阻塞是同一个操作** |

### 工程指标
- Python 3.10+，**仅一个运行时依赖**，380+ 项测试
- CI 覆盖 Linux / macOS / Windows 三平台
- Apache 2.0 开源许可证
- 两种接入方式：`pip install attune-forms` 或 Claude Code 插件（无需 Python 环境配置）

### 自举验证（Dogfooding）
- 构建该库过程中的每一个范围界定与设计决策，均通过该语法本身完成——三天内从 v0.1.0 迭代到 v0.4.0，实现了"用自己定义的语法来设计自己"的元验证。

## 核心痛点

1. **低效的多轮问答**：当前 AI 编码代理以自由文本聊天为唯一通道，独立决策被迫串行化为"二十个问题"，而 attune-forms 将其压缩为一次批量往返。
2. **结构缺失导致的静默错误**：自然语言提问与回答缺乏类型约束，格式错误、语义偏差会在双向流通中被静默接受，直至下游产生难排查的故障。
3. **用户与智能体之间的权力不对等**：传统交互中用户否决智能体往往被处理为"失败/异常"路径，缺乏一等公民的结构化表达——Pushback 机制将"否决"转化为合法且明确的一等结果。
4. **上下文割裂**：进度报告中的"阻塞项"与"解除阻塞的操作"是分离的（读完报告还要另发指令），Progress 结构将两者融合为同一手势，减少操作摩擦。
5. **插件生态割裂**：同一套表单逻辑需要在 HTML 前端、终端 CLI、MCP 协议等不同宿主环境中重复实现，schema 统一抽象解决了多端一致性问题。
