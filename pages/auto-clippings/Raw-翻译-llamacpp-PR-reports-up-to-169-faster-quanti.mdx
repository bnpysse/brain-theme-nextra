【帖子标题】：llama.cpp PR 报告在 Intel Battlemage 上使用 169% 更快的量化-KV 解码，来自一个 SYCL 内核切换

【帖子正文】：
一篇最新的 llama.cpp PR（#26689）似乎改变了 SYCL FlashAttention 分派决策中的一个小细节。

带有量化 KV 缓存（"q4_0" / "q8_0"），解码被发送到 VEC 内核。在作者的 Battlemage 测试系统上，将该路径切换为 TILE 随着上下文的增长而显著加快。

一些作者报告的结果（MTP 关闭）：

- Qwen3.6-35B，q4_0 KV @ 118,784：12.99 → 29.61 t/s (+127.9%)
- Qwen3.6-35B，q8_0 KV @ 118,784：12.90 → 31.80 t/s (+146.5%)
- Gemma 4 12B，q4_0 KV @ 118,784：5.06 → 13.59 t/s (+168.7%)
- Gemma 4 12B，q8_0 KV @ 118,784：5.13 → 13.81 t/s (+168.7%)

这不仅仅是在极端的 118K 点上。在 32K 上，相同的 JIT 测试显示，在测试过的 Qwen/Gemma 配置上大约 +42% 到 +74% 的提升。

有趣的部分是实际想法有多么微小。该 PR 基本上改变了分派门，使得量化-KV 解码选择 TILE 而不是被强制通过 VEC，并添加了 "GGML_SYCL_FA_DECODE_KERNEL=vec|tile|auto" 以便进行 A/B 测试。

需要注意的几个重要事项：

- 此 PR 尚未合并
- 这些主要是作者报告的基准测试结果
- PR 中没有明确指定确切的 Battlemage GPU SKU
- 该 PR 特别针对量化 KV；F16 维持现有分派
- 仅有一个 118K MTP 测试从 17.65 → 20.14 t/s (+14.1%)
- 后端测试通过了 4001/4001，但尚未进行独立的硬件扫描

此外，PR 还引用了一个 Laguna-S-2.1 Discord 测试，在 64K 上提升了 +50%，在 118K 上提升了 +68%，但我仍然希望看到更正式的独立结果。
