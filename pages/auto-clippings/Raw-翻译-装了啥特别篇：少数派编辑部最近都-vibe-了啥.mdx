【文章标题】：装了啥特别篇：少数派编辑部最近都 vibe 了啥？

【文章正文】：
如今，vibe coding 的话题热度居高不下。但抛开那些被吹上天的一人公司「壮举」，vibe coding 能给一般用户的日常使用带来什么帮助呢？本期「装了啥」中，编辑部成员就分享了一些近期折腾出的小玩意，并回顾了这些需求的起因、借助 AI 工具开发的真实过程，以及关键的提示词设计思路，希望对你有所启发。
自制天气看板
@PlatyHsu: 虽然 vibe coding 上新闻的用例都是那些以一当十、一个月抵过去一年的壮举，但对于非从业人士来说，我想它更大的意义还是能帮你实现各种过于小众而无人会照顾的需求。这些需求的实现可能非常简陋，以至于不配称为一个「产品」，但精雕细琢本来也就不需要是一个目标。
以我为例，虽然身处深圳，但我更喜欢看香港天文台的预报。一是因为两城足够接近，天气资讯可以交叉参考；另外我也更喜欢香港天文台的预报写法，即除了预报结论外还会描述有关天气系统和天气过程，让人更加知其所以然。（尽管这未必代表结论更准确，或者说在广东这种福地也很难准确。）
不过，在官网的使用体验方面，香港天文台和深圳气象局只能说是难兄难弟，都充斥着各种上古设计和技术，香港天文台甚至还更卡一些。如果隔几个小时就手动访问的话，可能浪费的时间已经够一场骤雨了。因此，我希望做一个简单的网页来汇总两地的预报。
那么从何入手呢？我的观点是，虽然把 AI 当作许愿机未尝不可，但最好还是能自己做一些研究，在提示词阶段就给出数据源、部署方式和设计等方面的具体要求，这样既节省 token 也节省时间。
具体到我的需求而言——
1. 数据源。访问深圳气象局的预报页面，打开浏览器的 Devtools 后刷新页面，即可看到大量指向 weather.121.com.cn 域名的请求。点开几个请求查看其响应内容，可知 https://weather.121.com.cn/data_cache/szWeather/sz10day_new.js 是天气、降水、温度等预报数据，而 https://weather.121.com.cn/data_cache/szWeather/szImportantTips.js 是对天气趋势的文字说明（也即官方微博发布的主要内容）。
香港天文台的数据则更简单。翻阅网站菜单即可发现它提供了官方的 RSS 订阅源 https://rss.weather.gov.hk/rss/SeveralDaysWeatherForecast_uc.xml，其中就有我所需的各种信息。
最后，考虑到深圳气象局和香港天文台一般每天更新 4 次左右预报，每小时检查一次就能获得及时的信息了。由于我们是 vibe coding，探索到这一步即可，至于数据的读取和清洗整理，AI 有能力自行解决。
2. 部署方式。对于这种简单的信息抓取和呈现用例，我习惯使用 Cloudflare Workers 搭配 KV 来部署，其中 Workers 负责抓取数据和呈现网页，KV 负责数据存储。同类选择也有很多，不过 Cloudflare 有着慷慨的免费方案和清晰简明的控制台，我用下来相对更顺手一些。
至于具体的部署步骤则不用担心，由于 Cloudflare 有完整的文档和命令行界面 wrangler，只要提供登录凭据，剩下的操作，当前主流模型都足以代劳。（Cloudflare 默认使用 workers.dev 域名；如果需要便于国内访问，可以额外绑定一个自定义域名。）
3. 设计。由于这个工具只是我自己使用，目标是越简洁越好。因此，我一般会告诉模型使用 vanilla HTML and JS，并且使用 minimalistic, text-first 的设计风格，以抑制模型一言不合就喜欢使用 JS 框架、用迷幻色彩和大面积阴影的倾向。
在确定上述需求之后，提示词也就水到渠成了。我当时使用 Claude Opus 4.6 模型，一次就达到了相当可用的效果；再针对细节设计做一些调整，一个小时内便实现了我这个小众需求。
通过类似的思路，我还在 AI 帮助下，为一些没有官方 RSS 的网站，通过定期检查页面内容的方式创建了 RSS 订阅链接，同样部署在 Cloudflare Workers 上，省下了 FiveFilters 之类服务的费用。有兴趣的朋友不妨探索。
自制插件解决收藏夹碎片化的问题
@张奕源Nick: 不知道你有没有这样的感觉或者困惑：社交媒体用久了，一定点过很多收藏，这些乱七八糟的东西批量整理起来非常麻烦。而且很多收藏过期之后就会消失，自己也搞不清楚到底有用没用。
所以我让 AI 写了两个 Chrome 浏览器插件来解决这个问题。
我最常用的两个社媒平台是微博和 X，两个插件（微博版、X 版）也分别针对这俩平台做了相应的功能。
大体思路是这样的：安装插件之后，当我看到想收藏的东西，直接点击旁边的收藏按钮即可。插件会把博文的文字、原图乃至原始影片都缓存在电脑本地一个文件夹里，相当于把原博永久缓存了。
当我觉得积攒到一定数量、需要汇总一下之后，再点另一个按钮，插件就会把当前本地的所有博文汇编成 .enex 文件，我可以随时存入我的《Evernote》，进一步整理或者归档。
Vibe Coding 的过程还是很 Vibe 的，我只在一开始提出了明确的目标：
    帮我设计一个微博抓取工具、脚本或者插件，我想要做的事情是：
核心目标：把我的微博收藏夹重新整理并迁移到其它笔记软体里，如 Evernote。
需要做的事情：提取每条微博的文字、图片、链接或其它元素，并且有序地存放在一个地方（譬如本地文件夹），如果能直接转成可以在线保存到 Evernote 或者 Notion 的笔记更好。
我一开始的想法是看看有没有什么通用方案，能让这个插件导出类似 markdown 加媒体附件的东西，这样就可以不受笔记工具的限制，任意二次使用。后来我考虑到自己主要在用《Evernote》，不如一次性点对点，把导出 .enex 也做了。
在 Vibe 的过程中，我开始逐渐加入更细节的要求，譬如：
- 把插件图标改成对应社媒平台加《Evernote》大象头的组合，更容易分辨
- 加入标签机制，这样导入《Evernote》之后笔记不会乱
- 优化按钮的位置，避免占用太多空间
就在写这篇文章的时候，我又迭代了一下，解决了不能保存长微博全文的问题。X-Evernote 目前还有本地文件夹访问权限的授权问题，正在 Vibe 中。
保存到《Evernote》这个功能在国内肯定比较小众，所以如果你需要类似功能但想导出到别处，可以让 AI 直接抓取 Github 项目，并且 fork 一个你自己的版本。提示词可以是「修改这个项目，将导出部分改为⋯⋯」，排查错误的工作也交给 AI 就行，它一定会帮你捣鼓到你想要的程度的。
另外，《Evernote》限制了导入笔记的结构，任何新导入的笔记都必须是一个单独的笔记本（Notebook）而非子文件夹，所以每次导入笔记过后需要简单整理一下，删除多余的笔记本。这一点受《Evernote》设计思路所限，已经没有优化空间了。如果你用《Notion》或者《Obsidian》之类的笔记工具，折腾的空间应该会更大。
自动检查并禁用 Windows 自动更新
@张奕源Nick: 用过 Windows 的朋友们肯定都体验过「东西搞到一半放在那儿，第二天醒来电脑自动更新重启了」的窘境。市面上有很多停用 Windows 自动更新和重启的方案，有的简单有的复杂，有的临时有的长久，我也尝试过其中一些。但只要你主动更新过系统，阻拦方案就很容易失效，还要重新配置，相当麻烦。
再又一次自动重启把握时机气到想砸电脑之后，我决定让 ChatGPT 帮我解决这个问题。
整套方案其实不复杂，AI 能做的事跟人类一样，无非就是先禁用系统自动更新功能，然后停用对应的服务。相当于系统更新这个功能都被干掉了，自动重启的问题自然也就不存在了。
但 AI 的方案优势在于，它额外写了个守护进程脚本，会在每次电脑重启时自动启动一次，排查当前系统更新的状态。如果觉得不对劲，它会重新执行一次上面提到的禁用命令，确保把系统更新扼杀在萌芽状态。
提示词也非常非常简单，没有任何技巧，我只是告诉 GPT 让它彻底帮我解决 Windows 自动更新并重启的问题，GPT 就拿出了这个方案。我唯一做的调整是：GPT 感受到了我的愤怒之情，所以一开始的守护程序搞得很激进，每小时侦测一次系统状态。我觉得没有必要，于是让它改成了每次开机或重启检测一次就行。
顺带一提，目前主流 AI 的客户端几乎都能执行本地操作，所以很多类似的功能执行和故障排查交给 AI 完成就好。尤其遇到不明所以的卡顿、驱动错误之类，AI 往往能通过翻阅系统日志、注册表之类的方式精准定位问题所在，比在网上翻帖子、凭感觉手搓强很多。
我之前就遇到过 Windows 资源管理器启动慢的问题，ChatGPT 帮我一通排查之后顺利解决。我至今都不知道问题出在哪里，只看到 GPT 留下的一堆脚本。
如果你也有类似的困惑，可以大胆求助 AI。

自制符合特定需求的视频转码工具
@广陵止息：众所周知，ffmpeg 是一个功能极其强大的多媒体处理工具，不少专业软件和项目，例如 DaVinci Resolve、Jellyfin 和 OBS，也会用到它。不过，参数复杂、命令冗长，再加上不同功能之间存在大量组合关系，也让 ffmpeg 有着不低的上手门槛。
这就带来了一个问题：哪怕只是做简单的批量转码，往往也得先研究文档，才能写出合适的命令或脚本。因此，更多人会选择带有 GUI 的相关工具，比如国内比较常见的格式工厂，或者开源的 HandBrake。
